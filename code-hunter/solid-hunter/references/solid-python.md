# SOLID Hunter — Python reference

Contents: Applicability of the categories · Generated-code and test-path eligibility · Python principles · Per-category Python content · Framework carve-outs — name the construct · Phase 2 — solid scans

## Applicability of the categories

| Category | Applicable | Unit | Note |
| -------- | ---------- | ---- | ---- |
| Responsibility Sprawl (SRP) | **yes** | class | A module of plain functions is functional style, not a class subject; record the style |
| Rigid Extension Points (OCP) | **yes** | any discriminant: a `str` / `Enum` / `Literal` kind, a `bool` parameter | |
| Broken Substitution (LSP) | **yes** | ABC and Protocol implementors, and subclasses | Both inheritance and structural satisfaction apply |
| Fat Interfaces (ISP) | **yes** | ABC, Protocol | Existence test decides ownership before width |
| Concrete Dependency Chains (DIP) | **yes** | class | |

## Generated-code and test-path eligibility

Generated-code markers, where one exists: `# Generated by …`, `# @generated`, protobuf and gRPC stub headers. The
scan globs `*_pb2.py` / `*_pb2_grpc.py` approximate them.

Vendored and build trees (`venv/`, `.venv/`, `dist/`, `build/`, `__pycache__/`, `*.egg-info/`), lockfiles, and
Markdown-only inputs are also ineligible.

**Test paths are ineligible** (see Test-code scope in SKILL.md): `test_*.py`, `*_test.py`, `tests/`, `conftest.py`.

## Python principles

- **Duck typing is the default seam.** A collaborator does not need a declared abstraction to be substitutable; a
  shape-compatible fake passes. This is why injecting the concrete type is a sufficient DIP remedy here.
- **Protocol (structural) and ABC (nominal) are both abstractions.** A Protocol implementor carries no `implements`
  marker and no base class — it is found by reading consumers, not by scanning subclass syntax. `@abstractmethod`
  membership is what ISP counts on an ABC.
- **Composition roots are explicit or framework-provided:** an app factory (`create_app()`), a container module, a
  `main()`, FastAPI `Depends` providers, a `dependency_injector` container.

## Per-category Python content

### Rigid Extension Points — Python forms

`if/elif` chains and `match` statements on a `str`, `Enum`, or `Literal` discriminant across several modules; a factory
function whose `if/elif` grows per variant with no registry; `if urgent:` selecting a channel at several sites. Remedy
vocabulary, smallest first: a `dict[Kind, X]` lookup when the arms select a value; one shared function when the arms
differ by a single call; a Protocol with one implementation per variant, dispatched through a `dict[Kind, Protocol]`,
only when the arms carry behavior.

Exhaustiveness — `case _: assert_never(x)`, pyright's `reportMatchNotExhaustive` — is invariant-hunter's and never
decides openness here.

### Broken Substitution — Python forms

- An override or implementor that raises `NotImplementedError` on a member the base declares as working behavior — an
  `@abstractmethod` body raising `NotImplementedError` is the *declaration*, not a violation
- An override that silently returns `None` or an empty container instead of performing the base behavior
- An override that narrows accepted input, or raises where the base contract implies success
- A consumer branch that compensates: `if isinstance(repo, InMemoryRepo): return  # no transaction support`, inside a
  service typed against `Repository` whose ABC declares `transaction()`

`if isinstance(repo, PostgresRepo): repo.vacuum()` where `vacuum` is outside `Repository` unlocks an extra — no
finding. `isinstance(node, Leaf)` over `Node = Leaf | Branch` dataclasses narrows a **data variant set** —
invariant-hunter's, not here.

### Fat Interfaces — Python forms

Count `@abstractmethod` members on an ABC, and the declared members on a Protocol. The seam test comes first: a
Protocol or ABC that no production consumer receives from outside, with one implementor and no double, is
simplicity-hunter's Unnecessary Abstractions. A live seam plus consumers using disjoint subsets is the finding here.
Remedy vocabulary: split into role Protocols (`Readable`, `Writable`) and annotate each consumer with the slice it
uses; the consumer that needs everything keeps the composite.

### Concrete Dependency Chains — Python forms

The finding is a class that **creates and keeps** a service: `self.mailer = SmtpMailer()` in `__init__`, or a method
that builds a client per call. A module-level client (`_db = psycopg.connect(...)`) read inside business logic is the
global-read form, anchored at the reading class.

Not findings: `self.parser = CsvParser()` — a pure in-process helper; `UserService(mailer: SmtpMailer)` accepting the
mailer — a concrete parameter is not creation; `open(path)` inside one method on a path the method received; any
dataclass, `NamedTuple`, or builder construction. A `datetime.now()`, `time.time()`, or `random.*` call inside
business logic is the **Low** form of this finding — a clock or random source the caller cannot control — reported
only when the Evidence names what that costs.

## Framework carve-outs — name the construct

- **FastAPI `Depends`** — both forms: `def handler(svc: Svc = Depends(get_svc))` and
  `def handler(svc: Annotated[Svc, Depends(get_svc)])`. The provider function is the composition root; the parameter is
  injected, not created.
- **Django class-based views** — the handler shape (`get`, `post`, `dispatch`, `get_queryset`) is prescribed: its
  existence and signature are exempt. The body is evaluated normally, and a `get()` that renders, mails and audits is
  simplicity-hunter's Mixed Concerns — cross-reference. Members *outside* the prescribed shape that serve a second
  actor are a Responsibility Sprawl finding at the class.
- **`dependency_injector` / `punq` / app-factory containers** — registration modules are composition roots, and a
  container-resolved dependency counts as a live seam.
- **pytest fixtures** — test-path, out of scope; read as context only.

## Phase 2 — solid scans

`$PY_FILES` is this language's eligible list, restored from `<run>/python.txt` (SKILL.md Phase 1 step 4); test files
are already out of it. A scan that needs a narrower list derives it by filtering that list, e.g.
`printf '%s\n' $PY_FILES | grep -v '_test\.py$'`. That works for `.` too, because the globs then apply. **Scans
nominate only.**

```bash
EXCLUDE='--glob !**/venv/** --glob !**/.venv/** --glob !**/dist/** --glob !**/build/** --glob !**/__pycache__/** --glob !**/*.egg-info/** --glob !**/*_pb2.py --glob !**/*_pb2_grpc.py --glob !**/test_*.py --glob !**/*_test.py --glob !**/tests/** --glob !**/conftest.py'

# Responsibility Sprawl: classes and their constructors (then read the members and name the actors)
rg -H -n '^\s*class\s+\w+' --type py $EXCLUDE -- $PY_FILES
rg -H -n 'def\s+__init__\s*\(' --type py $EXCLUDE -- $PY_FILES

# Fat Interfaces / Broken Substitution: abstractions and their declared members
rg -H -n --pcre2 'class\s+\w+\s*\([^)]*\b(ABC|Protocol)\b' --type py $EXCLUDE -- $PY_FILES
rg -H -n '@abstractmethod' --type py $EXCLUDE -- $PY_FILES

# Broken Substitution: inheritance edges, not-implemented bodies, consumer narrowing
rg -H -n --pcre2 'class\s+\w+\s*\([^)]+\)' --type py $EXCLUDE -- $PY_FILES
rg -H -n 'NotImplementedError|raise\s+NotImplemented' --type py $EXCLUDE -- $PY_FILES
rg -H -n 'isinstance\s*\(' --type py $EXCLUDE -- $PY_FILES

# Rigid Extension Points: discriminant chains, match statements, boolean parameters
rg -H -n '^\s*elif\s' --type py $EXCLUDE -- $PY_FILES
rg -H -n '^\s*match\s+\w' --type py $EXCLUDE -- $PY_FILES
rg -H -n --pcre2 'def\s+\w+\([^)]*\b\w+\s*:\s*bool\b' --type py $EXCLUDE -- $PY_FILES

# Concrete Dependency Chains: a call result assigned to an attribute — `SmtpMailer()`, `requests.Session()`,
# `psycopg.connect(...)`, `boto3.client(...)`; fires on values too, filter while reading
rg -H -n --pcre2 'self\.\w+\s*=\s*(\w+\.)*\w+\(' --type py $EXCLUDE -- $PY_FILES

# Concrete Dependency Chains: a clock or random source read inside logic (the Low form)
rg -H -n 'datetime\.now\(|datetime\.utcnow\(|time\.time\(|random\.\w+\(' --type py $EXCLUDE -- $PY_FILES

# Concrete Dependency Chains: module-level clients (then find the methods that read them)
rg -H -n --pcre2 '^\w+\s*=\s*\w*\.?(connect|Client|Session|Engine|create_engine|Redis)\(' --type py $EXCLUDE -- $PY_FILES

# Composition-root nomination (behavior decides; these only point the search)
rg -H -n 'Depends\(|create_app|containers\.|providers\.|if\s+__name__\s*==' --type py $EXCLUDE -- $PY_FILES
```
