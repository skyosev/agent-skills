# Security Hunter — TypeScript reference

Contents: Applicability · Generated-code and test-path eligibility · Language facts and version gates · Not a finding on these grounds alone — TypeScript · Boundary inventory · Detectors · Phase 3 — security scans · Phase 5 — TypeScript-specific evaluation

## Applicability

| Category | Applicable | TypeScript note |
| -------- | ---------- | --------------- |
| Hardcoded Secrets | **yes** | `security-common.md` scans; `const apiKey: string = "…"` included; a public env prefix with a secret name is Sensitive Data Exposure |
| Injection | **yes** | raw SQL APIs, NoSQL filters from the request, `eval` / `Function` / `child_process`, `fs` on input, DOM and framework HTML sinks, `fetch(url)`, redirects, response headers, recursive merges (`proto`) |
| Unvalidated Boundary Input | **yes, no CGO** | `create(req.body)` and other whole-body writes; a route that skips the schema its peers parse; server-action arguments |
| Insecure Configuration | **yes** | `rejectUnauthorized: false`, CORS, cookie and session options, CSP, `trust proxy`, GraphQL introspection and playground, WebSocket origin |
| Auth Gaps | **yes** | Express / Fastify / NestJS / Next.js / tRPC auth markers, `jwt.decode` / `decodeJwt`, webhook signatures, client claims |
| Sensitive Data Exposure | **yes** | log calls with credential words or the request; `err.message` / `err.stack` in responses; `localStorage` tokens; public env prefixes |
| Weak Cryptography | **yes** | `createHash('md5')`, `Math.random`, `createCipher`, `===` on a MAC, `jsonwebtoken` algorithm confusion, low bcrypt cost |
| Resource Exhaustion | **yes** | `new RegExp(input)` and literal nested quantifiers; body-parser and upload limits; GraphQL depth; `Promise.all` fan-out; WebSocket `maxPayload`; limiters |
| Dependency and Supply-Chain Risks | **yes** | `package.json` ranges and sources, lockfiles, the project's own `postinstall`, configured `npm audit` |

## Generated-code and test-path eligibility

A file is generated (ineligible for reporting) only when identified by an authoritative in-file marker. No
TypeScript-wide marker is defined; common ones are `// @generated`, `/* eslint-disable */ // Code generated by …`, and
the headers emitted by GraphQL Code Generator, Prisma, and `protoc-gen-ts`. When a project documents its own, apply
that. Scan globs such as `*.generated.*` / `__generated__/**` / `generated/**` are approximations for scanning
convenience.

Vendored and build trees (`node_modules/`, `dist/`, `build/`, `.next/`), declaration files (`*.d.ts`), lockfiles, and
Markdown-only inputs are also ineligible.

**Test paths are ineligible** (see Test-code scope in SKILL.md): `*.test.*`, `*.spec.*`, `*.e2e.*`, `__tests__/`.
Hardcoded Secrets still scans them through the all-file list.

## Language facts and version gates

The versions are the Node major from `engines.node` or `.nvmrc` (else `unknown`), and each library's version from the
lockfile when a candidate depends on it. A remedy is proposed only when the recorded version supports it; a default is
judged by that version.

- Express ≥ 4.16 and 5: `express.json()` default `limit` 100 kB. Express 5 `req.query` is a getter and the default
  query parser is `simple`; `qs` is used only when the app sets `query parser` to `extended` (Express 5 migration
  guide).
- NestJS on Express uses Express's 100 kB default. Fastify `bodyLimit` defaults to 1 MiB.
- Apollo Server 4 disables introspection when `NODE_ENV=production`: a finding only with an explicit
  `introspection: true`, or with `NODE_ENV` unset in the deployment evidence. Yoga and Mercurius are judged by their
  own defaults at the recorded version.
- `jsonwebtoken`: `decode()` never verifies. `verify()` without `algorithms`: on ≤ 8 it searches the key's text for
  `BEGIN CERTIFICATE` / `BEGIN PUBLIC KEY` / `BEGIN RSA PUBLIC KEY` and otherwise allows `HS*`, so a PEM string or a
  `Buffer` of one pins `RS*` / `PS*` / `ES*`, while a `KeyObject`, a DER `Buffer`, or a JWK-derived key lets an
  `HS256` token signed with the public key verify (`verify.js` v8.5.1); on ≥ 9 it defaults the list from the key type
  and rejects `HS*` with an asymmetric key before it reads `allowInvalidAsymmetricKeyTypes`, which only relaxes the
  family-to-key-type check (`verify.js` v9). An explicit `algorithms` list mixing `HS*` with a public key is algorithm
  confusion on every major.
- `jose`: `decodeJwt` never verifies; `jwtVerify` does.
- Next.js server actions (`"use server"`) receive untrusted arguments; route handlers receive a `Request`;
  `middleware.ts` is the usual auth boundary.
- `NODE_TLS_REJECT_UNAUTHORIZED=0` disables verification process-wide.
- A shallow spread defines `__proto__` as an own property and reaches no prototype. `Object.assign` with a
  `__proto__` key sets the target's prototype, never `Object.prototype`, so `Object.assign({}, body).isAdmin` reads
  `true` (Node 24). A recursive merge or a set-by-path with attacker-controlled keys can reach `Object.prototype`.
- `ws`: `maxPayload` defaults to 100 MiB (unset is that bound, not no bound); `0` means no limit.
- `express-session` defaults to `httpOnly: true` and `secure: false`.

## Not a finding on these grounds alone — TypeScript

- **`{ ...req.body }`** as `proto` (spread defines an own `__proto__`); **`Object.assign({}, body)`** whose every read
  is an own-property read, or whose result is only persisted (judged under Unvalidated Boundary Input).
- **A body parser, a `ws` server, a GraphQL server, or a `jwt.verify` call** that the Express, `ws`, Apollo, or
  `jsonwebtoken` gate (Language facts) clears at the recorded version.
- **A NestJS global `ValidationPipe` with `whitelist: true`**: framework-level validation for Unvalidated Boundary
  Input.
- **A missing `helmet`**: absence has no nominator.
- **`JSON.parse` of input without a `try` / `catch`**: not a security property.

## Boundary inventory

- **Routes:** Express 4 / 5 (`app.use` order, routers), Fastify (`preHandler`, `onRequest` hooks), NestJS controllers
  (`@Get`, `@Post`, …), Next.js (route handlers `export function GET`, server actions `"use server"`, API routes),
  tRPC (`publicProcedure` vs `protectedProcedure`), Hono, Koa, GraphQL (Apollo 4 `context`, Yoga, Mercurius;
  resolvers as routes), WebSocket (`ws` `verifyClient`, socket.io middleware, NestJS `@WebSocketGateway`), AWS Lambda
  handlers (`export const handler`), browser entry points (DOM sinks, `location`).
- **Other boundaries:** `process.argv` CLIs; `process.env` loaders; queue consumers (`@MessagePattern`,
  `@EventPattern`).
- **Auth:** middleware order in Express (`app.use(auth)` before the routers), Fastify hooks, NestJS `@UseGuards`,
  `APP_GUARD`, and `@Public()`; Next.js `export function middleware` in `middleware.ts` (the route scan nominates it,
  or the peer rule would report false `no-auth` rows); tRPC procedure builders; GraphQL `context` and resolver guards.

## Detectors

- **ESLint**, when the project configures it, from `node_modules/.bin/eslint` only (never `npx`, which can
  download); `skipped — configured, not installed` when that file is absent. The full configured rule set runs:
  ESLint cannot run only some configured rules. Without `--fix` and `--cache`, ESLint writes nothing. The JSON result
  carries each file's source, so the output is read only through the filter.

  ```bash
  TS_FILES=$(cat <run>/typescript.txt); [ -n "$TS_FILES" ] || exit 1  # STOP: empty restore
  EXCLUDE='--glob !**/node_modules/** --glob !**/dist/** --glob !**/build/** --glob !**/.next/** --glob !**/*.generated.* --glob !**/__generated__/** --glob !**/generated/** --glob !**/*.d.ts --glob !**/*.test.* --glob !**/*.spec.* --glob !**/*.e2e.* --glob !**/__tests__/**'
  [ "$TS_FILES" = . ] && TS_FILES=$(rg --files --type ts $EXCLUDE -- .)   # codebase mode: enumerate
  node_modules/.bin/eslint --format json $TS_FILES | node -e 'const keep=/^(security\/|no-unsanitized\/|@microsoft\/sdl\/(no-inner-html|no-document-write|no-insecure-url)$|react\/no-danger$)/;for(const f of JSON.parse(require("fs").readFileSync(0,"utf8")))for(const m of f.messages)if(m.fatal||keep.test(m.ruleId??""))console.log(`${f.filePath}:${m.line}: ${m.ruleId??"fatal"}: ${m.message}`)'
  ```

  Keep:
  - `eslint-plugin-security`: `detect-eval-with-expression` → Injection `code`; `detect-child-process` → Injection
    `command`; `detect-non-literal-fs-filename` → Injection `path`; `detect-non-literal-regexp` and
    `detect-unsafe-regex` → Resource Exhaustion `cpu`; `detect-possible-timing-attacks` and
    `detect-pseudoRandomBytes` → Weak Cryptography; `detect-object-injection` → dropped (noise with no sink).
  - `eslint-plugin-no-unsanitized`: `method`, `property` → Injection `html`.
  - `@microsoft/eslint-plugin-sdl`: `no-inner-html`, `no-document-write` → Injection `html`; `no-insecure-url` →
    Insecure Configuration.
  - `react/no-danger` → Injection `html` candidate.

  No security plugin configured → `skipped — no security-relevant rules enabled`.
- **npm audit / pnpm audit / yarn npm audit**, only when a package script or CI step runs it, with `--json`. It needs
  the network; unreachable → `errored`. `audit fix` is stripped. → Dependency and Supply-Chain Risks (`cve`), with
  the advisory id.

Blind spots: `.exec(` of a regex matches the command scan (reading drops it); routes behind a builder
(`route('/x').get(…)`) or a variable path; `fetch` through a wrapper client; a cookie set by a session library's
defaults (reading the options); JSX `href` built from input is scanned only as the literal `javascript:` scheme; Vue
and Svelte template files are in `security-common.md`, not here; an `Object.assign` whose polluted result is read
several calls later; a nested-quantifier pattern built with `RegExp` from a string holding escaped backslashes
(`detect-unsafe-regex` catches it when ESLint is configured); a missing `helmet` (absence has no nominator).

## Phase 5 — TypeScript-specific evaluation

- For each `jwt.decode` / `decodeJwt`: is a claim from it used for a decision, or only `kid` / `alg` before a
  `verify`?
- For each `jwt.verify`: apply the `jsonwebtoken` gate (Language facts) to the locked major, the `algorithms` list,
  and the key's form.
- For each literal pattern the nested-quantifier scan nominated: is it run on boundary input? A length cap does not
  close it.
- For each `cors(...)`: does `origin: true` or a reflecting function pair with `credentials: true`? Does the API use
  cookies or bearer tokens?
- For each `res.cookie` / session config: which cookie is the session? Are `httpOnly`, `secure`, and `sameSite` set,
  and what does the library default to at the recorded version?
- For each `express.json()` / `bodyParser`: is a `limit` set? Unset → the Express gate (Language facts); raised →
  judged against the route.
- For each `introspection: true` / `playground: true`: apply the Apollo gate (Language facts) to the server version and
  the deployment's `NODE_ENV`.
- For each `...req.body` / `create(req.body)` / `Object.assign` with request data: is the result persisted, or read
  for an inherited key? Does the model carry a privilege or ownership field (Auth Gaps) or a named column the route
  must not set (price, status, balance) that the body can reach? Is a `ValidationPipe` with `whitelist: true`, a
  `schema.pick()` / `.strict()`, or a stripping DTO in front, and does its schema declare that column?
- For each `Promise.all(list.map(…))`: is the list client-sized? Is there `p-limit` or a batch?
- For each WebSocket server: is a `verifyClient` or origin check present? Is `maxPayload` set to `0`, raised, or left at
  the `ws` default (Language facts) on a route whose messages never approach it? Is the handshake authenticated, or
  only the page that opened it?
- For each GraphQL server construction: is a depth or complexity rule in `validationRules`, or are persisted queries
  the only entry?
- For each Next.js route handler or server action: does `middleware.ts` match its path, and does it check the session?
