# Simplicity Hunter — report format

The report is, in order: `## Scope`; `## Findings` with one `###` section per category that has at least one finding;
`## Recommendations (Priority Order)`. Unbraced Scope lines appear on every run that reaches scanning; a `{braced}`
line appears only when its condition holds. A run that stops early (empty scope, no eligible source) writes the Scope
lines resolved so far and its `Audit completed` line, nothing else. A category with no findings gets no heading,
table, or "none found" line; a thin report is a valid result.

Language-only categories appended by a language reference (Go: Interface Pollution, Channel & Goroutine Overuse) use
the table schemas supplied in that reference.

**Row notes.** Under each table, one note per row, headed `#N`: the exact code the row cites, in a fenced block; then
each comment, commit or record that the row uses as evidence, quoted; then one clause for each item that applies — the
other reading a Within-skill precedence rule set aside, the answer to a two-behavior signal (Duplication rule 2), a
blocked probe, or a "remedy unresolved" counterexample (Drifted copies). In a run with more than one reader
(`references/orchestrator.md`), the first line of each note is the row-note line, which holds every clause that the
merge adds; the reader's note follows, its first line without its `#N — ` head:

```text
#<N> — Found by: <Claude | Codex | both> — from: <keys> — Claude checker: <keep | fix | drop | failed | not started> — Codex checker: <…>{ — dispute: dropped by <the Claude checker | the Codex checker | both checkers> under <rule>; kept: <reason>}{ — Action changed: <what changed>, by <the Claude checker | the Codex checker | this session>}{ — another area dropped it: <reason>}
#<N> — Found by: <Claude | Codex | both> — from: <keys> — not verified
```

The Codex checker clause appears only when Codex readers ran. An example:

```text
#1 — Found by: both — from: area 1 r1 Duplication #1; area 1 r2 Duplication #2 — Claude checker: keep — Codex checker: keep
other reading: Coexisting Generations; one copy is not a successor of the other
~~~ts
if (!body.email || !EMAIL_RE.test(body.email)) throw new ValidationError('email');
~~~
```

**Limitation lines.** One per open published unit whose negative claims were withdrawn:
`Limitation: {unit} open; {the signal that opened it}; consumer set not closed`. One per other withdrawn finding (an
uncertain dead path, a flag whose value lives outside the repository): `Limitation: {symbol} — {what could not be
verified}`.

