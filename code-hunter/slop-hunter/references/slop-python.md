# Slop Hunter — Python reference

Language-specific rules for Python. Every universal category applies; no language-only categories.

## Generated-code eligibility

A file is generated (ineligible for reporting) only when identified by an authoritative in-file marker **where one
exists** (`# Generated by …`, `# @generated`, protobuf and gRPC stub headers) — never by filename guessing. Scan
globs such as `*_pb2.py` / `*_pb2_grpc.py` are approximations for scanning convenience.

Vendored and build trees (`venv/`, `.venv/`, `dist/`, `build/`, `__pycache__/`, `*.egg-info/`), lockfiles, and
Markdown-only inputs are also ineligible.

Slop-hunter runs no scan globs: `$PY_FILES` is the eligible list itself. Test files (`test_*.py`, `*_test.py`,
`tests/`, `conftest.py`) are eligible.

```bash
# Diff / path mode: filter the manifest. Codebase mode: enumerate first.
# [ codebase ] CANDIDATES=$(rg --files --type py -- .)
PY_FILES=$(printf '%s\n' $CANDIDATES | rg '\.pyi?$' \
  | rg -v '(^|/)(venv|\.venv|dist|build|__pycache__)/|\.egg-info/' \
  | while read -r f; do rg -q -m1 '^#.*(Generated by|@generated|Protobuf Python Version|DO NOT EDIT)' "$f" || echo "$f"; done)
```

## Per-category Python markers

### Redundant Comments

Comment syntax is `#`. `# Initialize the list` above `items = []`; `# Loop through items` above `for item in items:`;
`# Handle the case where x is None` above `if x is None:` — the comment is slop; the guard itself, if already
guaranteed, is simplicity-hunter's.

### Verbose Documentation

Docstring style comes from the applicable config first — `[tool.ruff.lint.pydocstyle] convention` in
`pyproject.toml` / `ruff.toml` / `.ruff.toml` — then from the dominant style in nearby docstrings (Google, NumPy,
Sphinx). Markers:

- Docstrings on private (`_name`) helpers restating the name or body
- `:param name:` / `Args: name:` entries repeating the parameter name or annotation (`name: the name`)
- `:returns:` / `Returns:` restating the return annotation
- `__init__` docstrings listing the parameters assigned to `self`
- A block where every section is present and none adds anything beyond the signature

A public function keeps its summary line; whether that line is *right* is doc-hunter's.

### Style Drift

- `camelCase` where the project uses `snake_case`, or the reverse
- f-strings where the project uses `.format()` / `%`, or the reverse
- `pathlib` where the project uses `os.path`, or the reverse
- A loop where the project idiom is a comprehension, or the reverse
- Import ordering or grouping that breaks the project's (stdlib → third-party → local, or isort/Ruff `I` config)
- A different exception-handling pattern than established code (bare `except:`, `except Exception: pass`)
- Formatter output on touched lines (see Formatter)

Each of these is drift only against a resolved baseline. Two styles split evenly with no config → `baseline
uncertain`, no finding.

### Trivially Dead Code

- `import X` / `from m import X` where `X` has no use in the file (Python compiles it) — diff mode requires the
  merge-base proof
- `x = …` never referenced, with a side-effect-free initializer
- Leftover `pass` in a non-empty body
- Commented-out code (`# old_result = …`); `TODO` / `FIXME` without owner, ticket, or condition
- Bare `# noqa`, `# type: ignore`, `# pylint: disable=…`, `# pragma: no cover` with no trailing reason

Not a finding: `# noqa: F401` on a re-export in `__init__.py` with a stated reason or an `__all__` entry;
`# type: ignore[code]  # reason`.

Unused functions and constants → simplicity-hunter Dead Code Paths. Exported dead symbols → boundary-hunter.

### Hedging and Narration

Narration: `print(` in library code; `logger.debug("entering …")`, `logger.info("starting …")`, `logging.*("here")`.
Logging with a request ID, duration, or error context is operational and stays.

## Formatter

**Adoption:** the project invokes `ruff format` or `black` — in `Makefile`, `tox.ini`, `noxfile.py`, `justfile`,
`.pre-commit-config.yaml`, CI workflows, or a documented command. A `[tool.ruff]` or `[tool.black]` table alone is
**not** adoption: Ruff lint without Ruff format is common. Unsure → not adopted →
`skipped — no formatter adopted`.

**Execution:** `ruff format --check $PY_FILES` or `black --check $PY_FILES`. Not installed →
`skipped — <tool> not installed`. Never install. A non-format failure (syntax error, bad config) → `errored`.

In diff mode, `ruff format --diff <file>` / `black --diff <file>` gives the violating lines; keep only those inside
a `@@` range of `git diff -U0 "$MB" -- <file>`. Convention cell: `ruff format, touched line`.

Config resolution: Ruff uses the nearest `pyproject.toml` / `ruff.toml` / `.ruff.toml` up the tree; a monorepo may
have several baselines. Name the one that applied.

## Idiom calibration

Precedence: applicable formatter > project conventions > PEP 8. Fall back to PEP 8 only when the project has no
established convention; when PEP 8 is silent too, record `baseline uncertain`.

Docstrings on public API are convention, not slop. `pass` as the sole body of a protocol method or an intentionally
empty exception class is not leftover.

## Evidence path form

Cite findings as `file/path.py:line`.

## Phase 2 — slop scans

All scans take `$PY_FILES`. Diff mode keeps `@@` hunk headers so each `+` line maps to a working-tree line number;
untracked files have no diff and use the path-mode commands.

```bash
# ---- Diff mode: added lines only ----
# Patterns are anchored right after the leading +; start with .* to match anywhere on the line.
D() { git diff -U0 "$MB" -- $PY_FILES | rg "^@@|^\+($1)"; }

D '\s*#'                                                       # comments (classify manually)
D '.*("""|:param |:returns?:|Args:|Returns:)'                    # docstrings and tags
D '.*\b(TODO|FIXME|HACK|XXX)\b'                                # placeholder markers
D '.*#\s*(noqa|type:\s*ignore|pylint:\s*disable|pragma:\s*no cover)'   # suppressions (check for a reason)
D '\s*pass\s*$'                                                # leftover pass (then read the body)
D '\s*(import |from \S+ import )'                              # added imports (check uses in the file)
D '.*(print\(|logg(er|ing)\.\w+\(\s*["\x27](entering|exiting|starting|finished|begin|end|here))'   # narration
D '.*(?i)(workaround|might need|for safety|new, improved|improved version)'                       # hedging

# Removed lines: a removed use of a still-imported name nominates a Phase 4 candidate
git diff -U0 "$MB" -- $PY_FILES | rg '^-' | rg -v '^---'

# ---- Path / codebase mode: whole eligible files ----
rg -n '^\s*#' -- $PY_FILES                                     # comments (classify manually)
rg -n '"""' -- $PY_FILES                                       # docstring blocks
rg -n -B1 '^\s*def\s+_' -- $PY_FILES                           # docstrings on private helpers
rg -n '\b(TODO|FIXME|HACK|XXX)\b' -- $PY_FILES
rg -n '#\s*(noqa|type:\s*ignore|pylint:\s*disable|pragma:\s*no cover)' -- $PY_FILES
rg -n '^\s*pass\s*$' -- $PY_FILES
rg -n 'print\(|logg(er|ing)\.\w+\(\s*["\x27](entering|exiting|starting|finished|begin|end|here)' -- $PY_FILES
rg -n -i 'workaround|might need|for safety|new, improved|improved version' -- $PY_FILES

# Unused-import nomination (path mode): for each imported name, count uses outside the import line
# rg -c '\bNAME\b' FILE   → 1 means the import is the only mention

# ---- Formatter (Phase 3), only when adopted and installed ----
ruff format --check $PY_FILES      # or: black --check $PY_FILES
```

## Phase 5 — Python-specific evaluation

For each docstring candidate:

- Which style does the applicable config or the nearby code use? Judge the tags against that style.
- Does any section say something the signature and annotations do not? Strip only the sections that do not.

For each unused-import candidate in diff mode:

- Is the name used anywhere in the working-tree file (string references, `__all__`, decorators, type comments)?
- Was it used at the merge base (`git show "$MB:<file>" | rg '\bNAME\b'`)? No → pre-existing → not a finding.

For each suppression:

- Is there a trailing reason or an error code with a reason? Bare → Trivially Dead Code. Is the suppressed rule
  reporting something real? Severity Medium.

For each `pass`:

- Is it the sole statement of a deliberately empty body (protocol method, exception class, abstract stub)? Keep.
  Is it left in a body that now has other statements? Delete.

For each drift candidate:

- Which baseline source decided it — config, instruction, nearby code, or PEP 8? Name it, or drop the finding.
