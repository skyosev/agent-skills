# Slop Hunter — TypeScript reference

Contents: Generated-code eligibility · Per-category TypeScript markers · Formatter · Idiom calibration · Evidence path form · Phase 2 — slop scans · Phase 5 — TypeScript-specific evaluation

Language-specific rules for TypeScript. Every universal category applies; no language-only categories.

## Generated-code eligibility

A file is generated (ineligible for reporting) only when identified by an authoritative in-file marker — **never** by
filename guessing. No TypeScript-wide marker is defined; common ones are `// @generated`,
`/* eslint-disable */ // Code generated by …`, and the headers emitted by GraphQL Code Generator, Prisma, and
`protoc-gen-ts`. When a project documents its own, apply that. Scan globs such as `*.generated.*` / `__generated__/**`
/ `*.g.ts` / `generated/**` are approximations for scanning convenience.

Vendored and build trees (`node_modules/`, `dist/`, `build/`, `.next/`), lockfiles, and Markdown-only inputs are also
ineligible.

Slop-hunter runs no scan globs: `$TS_FILES` is the eligible list itself, so `foo.g.ts` without a marker is scanned
and a marked file is not. Test files (`*.test.*`, `*.spec.*`, `*.e2e.*`, `__tests__/`) are eligible.

```bash
cd "$(git rev-parse --show-toplevel)" || exit 1
CANDIDATES=$(cat <run>/scope.txt)              # diff / path: already a file list
# codebase:  CANDIDATES=$(rg --files --type ts)
TS_FILES=$(printf '%s\n' $CANDIDATES | rg '\.(ts|tsx|mts|cts)$' \
  | rg -v '(^|/)(node_modules|dist|build|\.next)/' \
  | while read -r f; do
      rg -q -m1 '^\s*(//|/\*|\*).*(@generated|Code generated by|DO NOT EDIT|This file was automatically generated)' "$f" \
        || echo "$f"
    done)
[ -n "$TS_FILES" ] && printf '%s\n' "$TS_FILES" > <run>/typescript.txt   # none eligible → no typescript.txt, no scans
```

## Per-category TypeScript markers

### Redundant Comments

Comment syntax is `//` and `/* */`. `// Initialize the array` above `const arr = []`; `// Return the result` above
`return result`; `// Check if user exists` above `if (!user)`.

### Verbose Documentation

JSDoc markers:

- JSDoc on a non-exported function restating its name or body
- `@param name - the name`; `@param {string} name` repeating a type the signature already declares
- `@returns` restating the return type
- `@description` narrating the implementation rather than the contract

An exported symbol keeps its summary line; whether it is *right* is doc-hunter's. JSDoc types (`{string}`) in a
TypeScript file are redundant with the signature unless the project generates docs from them — check for a `typedoc`
or `api-extractor` config before flagging.

### Style Drift

- `snake_case` where the project uses `camelCase`, or the reverse; `I`-prefixed interfaces where the project has none
- Template strings where the project uses concatenation, or the reverse
- Import ordering or grouping that breaks the project's (or its `import/order` / `simple-import-sort` config)
- A different error-handling pattern than established code (thrown strings, `catch (e: any)`, swallowed catches)
- `function` declarations where the project uses arrow constants, or the reverse
- Formatter output on touched lines (see Formatter)

Each of these is drift only against a resolved baseline. ESLint resolves the nearest config (`eslint.config.*`,
`.eslintrc.*`); Biome resolves `biome.json` / `biome.jsonc`. A monorepo may have several baselines — name the one
that applied.

### Trivially Dead Code

- `import { X } from '…'` where `X` has no use in the file — in diff mode an import present at the merge base needs
  the Phase 4 proof; an import this change added does not
- `const x = …` inside a function or block, never referenced, with a side-effect-free initializer. An unused
  top-level constant is simplicity-hunter's Dead Code Paths
- Commented-out code (`// const old = …`); `TODO` / `FIXME` without owner, ticket, or condition
- Bare `// eslint-disable`, `// eslint-disable-next-line <rule>`, `// biome-ignore lint/<rule>` with no trailing
  reason (`-- reason` for ESLint, `: reason` for Biome). `// @ts-ignore` and `// @ts-expect-error` are
  invariant-hunter's Type-System Bypasses, with or without a reason

Not a finding: `import type` kept for a declaration merge with a stated reason;
`export {}` making a file a module.

Unused functions and constants → simplicity-hunter Dead Code Paths. Unused exports → boundary-hunter Dead Exports.

### Hedging and Narration

Narration: `console.log` / `console.debug` / `console.info` with `'entering …'`, `'here'`, `'start'`, `'done'`, a
function name, or an unlabelled variable dump. Logging with a request ID, duration, or error context is operational
and stays.

## Formatter

**Adoption:** the project invokes `prettier` or `biome format` — a `package.json` script, `lint-staged`, a husky
hook, `.pre-commit-config.yaml`, or CI. A project running `biome check` with `formatter.enabled` in `biome.json` has
adopted Biome. A `.prettierrc` alone is **not** adoption. Unsure → not adopted → `skipped — no formatter adopted`.

**Execution:** `node_modules/.bin/prettier --list-different $TS_FILES` or `node_modules/.bin/biome format $TS_FILES`
(the nearest `node_modules` in a monorepo) — never `biome check`, which also lints. Not installed (no
`node_modules/.bin/<tool>`) → `skipped — <tool> not installed`. Never install. A non-format
failure (syntax error, bad config) → `errored`.

In diff mode, `prettier --check` names files only; get the violating lines from
`diff <(node_modules/.bin/prettier <file>) <file>` (or `node_modules/.bin/biome format <file>` output) and keep only
those inside a `@@` range of `git diff -U0 "$MB" -- <file>`. Convention cell: `prettier, touched line`.

## Idiom calibration

Baseline rung 4 (the Style Drift order in SKILL.md): none. TypeScript has no language-wide style guide, and the
presets a lint config extends belong to rung 1. No rung yields a convention → `baseline uncertain`.

Structural typing, `as const`, `satisfies`, discriminated unions, and type-only imports are the language working as
designed — never drift.

## Evidence path form

Cite findings as `file/path.ts:line` (or `.tsx` / `.mts` / `.cts` as appropriate).

## Phase 2 — slop scans

All scans take `$TS_FILES`, restored at the top of every call. Diff mode keeps the `+++` file headers and `@@` hunk
headers, so each `+` line maps to a file and a working-tree line number. Untracked files have no diff: diff mode
scans them whole with the whole-file commands, with `F` set to the untracked subset.

```bash
# ---- Every call: restore run state ----
cd "$(git rev-parse --show-toplevel)" || exit 1
TS_FILES=$(cat <run>/typescript.txt); [ -n "$TS_FILES" ] || exit 1   # STOP: empty restore

# ---- Diff mode: added lines only ----
MB=$(cat <run>/mb); [ -n "$MB" ] || exit 1                     # STOP: empty restore
# Patterns are anchored right after the leading +; start with .* to match anywhere on the line.
D() { git diff -U0 "$MB" -- $TS_FILES | rg "^\+\+\+ |^@@|^\+($1)"; }

D '\s*(//|/?\*)'                                             # comments and JSDoc (classify manually)
D '.*(@param|@returns?|@description)'                            # JSDoc tags
D '.*\b(TODO|FIXME|HACK|XXX)\b'                                # placeholder markers
D '.*(eslint-disable|biome-ignore)'                              # linter suppressions (check for a reason)
D '\s*import\s'                                                # added imports (check uses in the file)
D '.*console\.(log|debug|info)\('                              # narration candidates
D '.*(?i)(workaround|might need|for safety|new, improved|improved version)'   # hedging

# Removed lines, with file and hunk headers: a removed use of a still-imported name nominates a Phase 4 candidate
git diff -U0 "$MB" -- $TS_FILES | rg '^(\+\+\+ |@@|-)' | rg -v '^--- (a/|/dev/null)'

# ---- Whole-file scans ----
# path / codebase: F=$TS_FILES    diff (untracked files): F=$(git ls-files --others --exclude-standard -- $TS_FILES)
W() { [ -z "$F" ] || rg -nH "$@" -- $F; }                       # empty F must not search the whole tree
W '^\s*//'                                                     # comments (classify manually)
W '/\*\*'                                                      # JSDoc blocks
W -B2 '^\s*(async\s+)?function\s+[a-z]|^\s*const\s+[a-z]\w*\s*=\s*(async\s*)?\(' # non-exported functions with docs
W '\b(TODO|FIXME|HACK|XXX)\b'
W 'eslint-disable|biome-ignore'
W 'console\.(log|debug|info)\('
W -i 'workaround|might need|for safety|new, improved|improved version'

# Unused-import nomination (path mode): for each imported name, count uses outside the import line
# rg -c '\bNAME\b' FILE   → 1 means the import is the only mention

# ---- Formatter (Phase 3), only when adopted and installed ----
node_modules/.bin/prettier --list-different $TS_FILES      # or: node_modules/.bin/biome format $TS_FILES
```

## Phase 5 — TypeScript-specific evaluation

For each JSDoc candidate:

- Is the symbol exported? The summary line stays. Do the tags say anything the signature does not?
- Does the project generate docs from JSDoc (`typedoc`, `api-extractor`)? Then `@param` prose has a consumer;
  judge the prose, not the presence.

For each unused-import candidate in diff mode:

- Is the name used anywhere in the working-tree file — JSX tags, decorators, type positions, `typeof`?
- Import line added by this change → no proof needed; unused in the working tree → finding.
- Import line present at the merge base → `git show "$MB:<file>" | rg -c '\bNAME\b'` must be ≥ 2 (the import plus
  a use). 1 → pre-existing → not a finding.
- `noUnusedLocals` on in the applicable `tsconfig`? Re-open the file to confirm. If the import is unused, it slipped
  past `tsc` (bundlers such as esbuild and Vite do not type-check) and is a finding.

For each suppression:

- Is there a trailing reason (`-- reason`, `: reason`)? Bare → Trivially Dead Code. Is the suppressed rule reporting something real? Severity Medium.

For each `console.*`:

- Is this a CLI or script whose output *is* `console`? Then it is the interface, not narration.

For each drift candidate:

- Which baseline source decided it — the nearest ESLint/Biome config, an instruction file, nearby code, or the lint
  preset? Name it, or drop the finding.
