# Exception Hunter — TypeScript reference

Contents: Applicability · Generated-code and test-path eligibility · Language facts and version gates · Not a finding on these grounds alone — TypeScript · Transport frameworks · Delegated to tools · Phase 2 — exception scans · Phase 4 — TypeScript-specific evaluation

## Applicability

| Category | Applicable | TypeScript note |
| -------- | ---------- | --------------- |
| Swallowed Errors | **yes** | a default returned from `catch`; `.catch(() => {})`; `allSettled` results never read; `new Error(…)` never thrown |
| Orphaned Async Failures | no | floating promises and `async` callbacks are in Delegated to tools |
| Overbroad Handling | **yes** | a catch-all mapped to one meaning; retry predicates that accept everything; `AbortError` logged at error level |
| Broken Error Chains | **yes** | `options` not passed to `super`; `e.message` logged at the handling site |
| Unmatchable Failures | **yes** | `e.message` matching; `throw new Error(…)` where a caller branches on the kind |
| Untranslated Boundary Errors | **yes** | library codes and types matched outside the adapter; `HttpException` / `TRPCError` reached by a non-request entry point |
| Double Handling | **yes** | `console.error(e); throw e` |
| Poor Error Context | **yes** | literal messages with no input; interpolated `Sentry.captureMessage` |
| Panic and Exit Misuse | no | `process.exit` outside the entry point is in Delegated to tools |

## Generated-code and test-path eligibility

A file is generated (ineligible for reporting) only when identified by an authoritative in-file marker. No TypeScript-wide marker is defined; common ones are `// @generated`,
`/* eslint-disable */ // Code generated by …`, and the headers emitted by GraphQL Code Generator, Prisma, and
`protoc-gen-ts`. When a project documents its own, apply that. Scan globs such as `*.generated.*` / `__generated__/**`
/ `*.g.ts` / `generated/**` are approximations for scanning convenience.

Vendored and build trees (`node_modules/`, `dist/`, `build/`, `.next/`), lockfiles, and Markdown-only inputs are also
ineligible.

**Test paths are ineligible** (see Test-code scope in SKILL.md): `*.test.*`, `*.spec.*`, `*.e2e.*`, `__tests__/`.

## Language facts and version gates

The versions are tsconfig `target` and `lib`, and the Node major from `engines.node` or `.nvmrc`, else `unknown`
(SKILL.md Phase 1 step 5). A remedy is proposed only when the recorded versions support it.

- `Error.cause` needs `lib` (or `target`) `es2022` for the typing and Node ≥ 16.9 at runtime: an older runtime ignores
  the options argument, so the cause is still lost. With Node `unknown`, the Action says it needs 16.9.
- `AggregateError`: ES2021.

## Not a finding on these grounds alone — TypeScript

- **`err.code` of a Node system error** (`err.code === 'ENOENT'`): a documented code field, not text matching.

## Transport frameworks

- **Express 4 / 5**: the error middleware has four parameters (`(err, req, res, next)`).
- **NestJS**: the global exception filter maps an `HttpException` thrown anywhere on the request path.
- **Fastify**: `setErrorHandler`.
- **Next.js**: route handlers.
- **tRPC**: `TRPCError` carries the code.
- **Hono**: `onError`.

## Delegated to tools

- ESLint with typescript-eslint and eslint-plugin-unicorn, or Biome where a rule is named: a floating promise, `void`
  included (`@typescript-eslint/no-floating-promises` with `ignoreVoid: false`); an `async` callback whose promise is
  ignored (`no-misused-promises`); a `catch` that cannot run because a `return` inside its `try` has no `await`
  (`return-await`, `in-try-catch`); a thrown or rejected non-`Error` (`only-throw-error`,
  `prefer-promise-reject-errors`, or Biome `useThrowOnlyError`); an empty `catch` (`no-empty`, or Biome
  `noEmptyBlockStatements`); a jump in `finally` (`no-unsafe-finally`, or Biome `noUnsafeFinally`); a `catch` that
  only re-throws (`no-useless-catch`, or Biome `noUselessCatch`); a re-throw without `cause` (`preserve-caught-error`,
  with `errorClassNames` listing the project's error classes); `process.exit` outside the entry point
  (`unicorn/no-process-exit`). The typescript-eslint rules need type-aware linting (`parserOptions.projectService`).

## Phase 2 — exception scans

`$TS_FILES` is this language's eligible list, restored from `<run>/typescript.txt` (SKILL.md Phase 1 step 4).

```bash
EXCLUDE='--glob !**/node_modules/** --glob !**/dist/** --glob !**/build/** --glob !**/.next/** --glob !**/*.generated.* --glob !**/__generated__/** --glob !**/*.g.ts --glob !**/generated/** --glob !**/*.test.* --glob !**/*.spec.* --glob !**/*.e2e.* --glob !**/__tests__/**'

# Swallowed Errors: default return; .catch swallow; allSettled; unthrown errors
rg -H -n -U --pcre2 'catch\s*(\([^)]*\))?\s*\{\s*return(\s+(null|undefined|\[\]|\{\}|false|0|""|'"''"'))?\s*;?\s*\}' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 '\.catch\(\s*(noop|\(\s*\w*\s*\)\s*=>\s*(\{\s*\}|undefined|null|void 0|\[\]))\s*\)' --type ts $EXCLUDE -- $TS_FILES
rg -H -n 'allSettled\(' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 '^\s*new\s+\w*Error\(.*\);?\s*$' --type ts $EXCLUDE -- $TS_FILES
# Overbroad Handling: retry wrappers; cancellation
rg -H -n --pcre2 'retryIf|shouldRetry|p-retry|axios-retry|async-retry|\bretries\s*:' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 'AbortError|signal\.aborted|ABORT_ERR' --type ts $EXCLUDE -- $TS_FILES
# Overbroad Handling and Broken Error Chains: a new error thrown in a catch (then read whether it claims one meaning for
# every failure that reaches the catch, and whether it keeps the cause)
rg -H -n -U --pcre2 'catch\s*\(\s*(\w+)[^)]*\)\s*\{[^}]*?throw\s+new\s+\w+\([^;]*;' --type ts $EXCLUDE -- $TS_FILES
# Broken Error Chains: stack dropped at a log call; custom error classes (then read super())
rg -H -n --pcre2 '(console|log\w*)\.\w+\([^)]*\b(e|err|error|ex)\.message\b' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 'class\s+\w+\s+extends\s+\w*Error\b' --type ts $EXCLUDE -- $TS_FILES
# Unmatchable Failures: message matching
rg -H -n --pcre2 '\.message\s*(===?|!==?|\.(includes|startsWith|endsWith|match)\()' --type ts $EXCLUDE -- $TS_FILES
# Untranslated Boundary Errors: library codes and types (then compare the unit with the adapter); framework transport
# errors (then look for a non-request entry point that reaches the unit)
rg -H -n --pcre2 '\.code\s*[!=]==?\s*["'"'"'](P\d{4}|\d{5}|ER_\w+)["'"'"']|instanceof\s+(Prisma\.\w+|AxiosError|QueryFailedError|MongoServerError)|isAxiosError\(' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 'throw\s+new\s+(HttpException|(BadRequest|Unauthorized|Forbidden|NotFound|Conflict|Gone|UnprocessableEntity|InternalServerError|ServiceUnavailable)Exception|TRPCError|HTTPError)\(' --type ts $EXCLUDE -- $TS_FILES
# Swallowed Errors (logged-only) and Double Handling: a catch that logs first (then read whether it throws,
# continues, or returns a default)
rg -H -n -U --pcre2 'catch\s*(\([^)]*\))?\s*\{\s*(console|log\w*)\.\w+\(' --type ts $EXCLUDE -- $TS_FILES
# Poor Error Context: literal messages (then judge); message events only with a Tracker line (then read Sentry.init)
rg -H -n --pcre2 'throw\s+new\s+\w*Error\(\s*["'"'"'][^"'"'"'$]*["'"'"']\s*\)' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 'Sentry\.captureMessage\(\s*`[^`]*\$\{' --type ts $EXCLUDE -- $TS_FILES
```

Blind spots: a catch body with nested braces defeats the new-error-in-catch scan; a project's own `HttpException`
subclass (reading, from the boundary pass).

## Phase 4 — TypeScript-specific evaluation

- For each `catch`: is the binding narrowed before use (an unnarrowed `e.message` is invariant-hunter's)?
- For each custom error class that drops `options`: does any call site pass `{ cause }`? None → drop.
- For each transport error: does a non-request entry point reach the unit that throws it?
