# Exception Hunter — TypeScript reference

Contents: Applicability · Generated-code and test-path eligibility · Language facts and version gates · Not a finding on these grounds alone — TypeScript · Transport frameworks · Detectors · Phase 3 — exception scans · Phase 5 — TypeScript-specific evaluation

## Applicability

| Category | Applicable | TypeScript note |
| -------- | ---------- | --------------- |
| Swallowed Errors | **yes** | empty `catch`; a default returned from `catch`; `.catch(() => {})`; `return` in `finally`; `allSettled` results never read; `new Error(…)` never thrown |
| Orphaned Async Failures | **yes** | floating promises; `async` callbacks whose promise is ignored; `async` Express 4 routes with no wrapper; `void` on a callee that can reject |
| Overbroad Handling | **yes** | a catch-all mapped to one meaning; retry predicates that accept everything; `AbortError` logged at error level |
| Broken Error Chains | **yes** | a rethrow without `{ cause }`; `options` not passed to `super`; non-`Error` throws; `e.message` logged at the handling site |
| Unmatchable Failures | **yes** | `e.message` matching; `throw new Error(…)` where a caller branches on the kind |
| Untranslated Boundary Errors | **yes** | library codes and types matched outside the adapter; `HttpException` / `TRPCError` reached by a non-request entry point |
| Double Handling | **yes** | `console.error(e); throw e`; `catch (e) { throw e }` |
| Poor Error Context | **yes** | literal messages with no input; interpolated `Sentry.captureMessage` |
| Panic and Exit Misuse | **yes, exit calls only** | `process.exit` outside the entry point |

## Generated-code and test-path eligibility

A file is generated (ineligible for reporting) only when identified by an authoritative in-file marker. No TypeScript-wide marker is defined; common ones are `// @generated`,
`/* eslint-disable */ // Code generated by …`, and the headers emitted by GraphQL Code Generator, Prisma, and
`protoc-gen-ts`. When a project documents its own, apply that. Scan globs such as `*.generated.*` / `__generated__/**`
/ `*.g.ts` / `generated/**` are approximations for scanning convenience.

Vendored and build trees (`node_modules/`, `dist/`, `build/`, `.next/`), lockfiles, and Markdown-only inputs are also
ineligible.

**Test paths are ineligible** (see Test-code scope in SKILL.md): `*.test.*`, `*.spec.*`, `*.e2e.*`, `__tests__/`.

## Language facts and version gates

The versions are tsconfig `target` and `lib`, the Node major from `engines.node` or `.nvmrc` (else `unknown`), and
each package's Express major and async wrapper (SKILL.md Phase 1 step 5). A remedy is proposed only when the recorded
versions support it.

- `Error.cause` needs `lib` (or `target`) `es2022` for the typing and Node ≥ 16.9 at runtime: an older runtime ignores
  the options argument, so the cause is still lost. With Node `unknown`, the Action says it needs 16.9.
- `AggregateError`: ES2021.
- Node ≥ 15 crashes on an unhandled rejection by default. With Node `unknown`, the Consequence cell says "crash on
  Node ≥ 15".
- Express 5 forwards a rejected promise from an `async` handler to the error middleware; Express 4 does not.

## Not a finding on these grounds alone — TypeScript

- **A discarded promise whose callee catches every failure itself** and does not rethrow, confirmed by reading the
  callee, not by a comment.
- **`err.code` of a Node system error** (`err.code === 'ENOENT'`): a documented code field, not text matching.

## Transport frameworks

- **Express 4 / 5**: the error middleware has four parameters (`(err, req, res, next)`). Express 4 needs an async
  wrapper (`express-async-errors`, or a local wrapper applied to the routes) for `async` handlers; Express 5 forwards
  their rejections.
- **NestJS**: the global exception filter maps an `HttpException` thrown anywhere on the request path.
- **Fastify**: `setErrorHandler`.
- **Next.js**: route handlers.
- **tRPC**: `TRPCError` carries the code.
- **Hono**: `onError`.

## Detectors

Checked on ESLint 10.13.0, typescript-eslint 8.72.0.

**ESLint** runs when the project configures it (`eslint.config.*`, `.eslintrc.*`, an `eslintConfig` key in
`package.json`), from `node_modules/.bin/eslint` only; it is `skipped — configured, not installed` when that file is
absent. Never use `npx`, which can download.

```bash
cd "$(git rev-parse --show-toplevel)" || exit 1
TS_FILES=$(cat <run>/typescript.txt); [ -n "$TS_FILES" ] || exit 1  # STOP: empty restore
EXCLUDE='--glob !**/node_modules/** --glob !**/dist/** --glob !**/build/** --glob !**/.next/** --glob !**/*.generated.* --glob !**/__generated__/** --glob !**/*.g.ts --glob !**/generated/** --glob !**/*.test.* --glob !**/*.spec.* --glob !**/*.e2e.* --glob !**/__tests__/**'
[ "$TS_FILES" = . ] && TS_FILES=$(rg --files --type ts $EXCLUDE -- .)   # codebase mode: enumerate
node_modules/.bin/eslint --format json $TS_FILES | node -e 'const keep=/^(@typescript-eslint\/(no-floating-promises|no-misused-promises|return-await|only-throw-error)|(@typescript-eslint\/)?prefer-promise-reject-errors|preserve-caught-error|no-throw-literal|no-useless-catch|no-unsafe-finally|no-empty)$/;for(const f of JSON.parse(require("fs").readFileSync(0,"utf8")))for(const m of f.messages)if(m.fatal||keep.test(m.ruleId??""))console.log(`${f.filePath}:${m.line}: ${m.ruleId??"fatal"}: ${m.message}`)'
```

The full configured rule set runs: ESLint cannot run only some configured rules. Without `--fix` and `--cache`,
ESLint writes nothing. The JSON result of each file with a message carries the file's whole source, so the output is
read only through the filter. The filter keeps `fatal` lines (a file ESLint could not parse; its silence there is not
coverage) and these rules:

- `@typescript-eslint/no-floating-promises`, `no-misused-promises` → Orphaned Async Failures.
- `@typescript-eslint/return-await` (default `in-try-catch`) → routing rule 8 (a `catch` that cannot run).
- `preserve-caught-error` (core; its rule metadata marks it recommended in ESLint 10.13.0) → Broken Error Chains. It
  checks only built-in error constructors unless `errorClassNames` lists the project's classes, so a custom class
  thrown without `cause` needs the scan.
- `@typescript-eslint/only-throw-error`, `prefer-promise-reject-errors`, core `no-throw-literal` → Broken Error
  Chains (no stack).
- `no-useless-catch` → Double Handling.
- `no-unsafe-finally` → Swallowed Errors (`overridden`).
- `no-empty` (an empty `catch`, unless `allowEmptyCatch`) → Swallowed Errors.

**Outcome rules:** `no-floating-promises` not configured → one Low recommendation to adopt it (it needs type-aware
linting via `parserOptions.project` or `projectService`); regex cannot see a floating promise in general. Do not
install or reconfigure to run the audit. No other linter is recommended.

## Phase 3 — exception scans

`$TS_FILES` is this language's eligible list, restored from `<run>/typescript.txt` (SKILL.md Phase 1 step 4).

```bash
EXCLUDE='--glob !**/node_modules/** --glob !**/dist/** --glob !**/build/** --glob !**/.next/** --glob !**/*.generated.* --glob !**/__generated__/** --glob !**/*.g.ts --glob !**/generated/** --glob !**/*.test.* --glob !**/*.spec.* --glob !**/*.e2e.* --glob !**/__tests__/**'

# Swallowed Errors: empty catch (with or without a binding); default return; .catch swallow; return in finally; unthrown errors
rg -H -n --pcre2 'catch\s*(\([^)]*\))?\s*\{\s*\}' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 'catch\s*(\([^)]*\))?\s*\{\s*return(\s+(null|undefined|\[\]|\{\}|false|0|""|'"''"'))?\s*;?\s*\}' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 '\.catch\(\s*(noop|\(\s*\w*\s*\)\s*=>\s*(\{\s*\}|undefined|null|void 0|\[\]))\s*\)' --type ts $EXCLUDE -- $TS_FILES
rg -H -n -U --pcre2 'finally\s*\{[^}]*\breturn\b' --type ts $EXCLUDE -- $TS_FILES
rg -H -n 'allSettled\(' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 '^\s*new\s+\w*Error\(.*\);?\s*$' --type ts $EXCLUDE -- $TS_FILES
# Orphaned Async Failures: async callbacks whose promise is ignored; async route handlers (then read the package's
# Express major and wrapper); void discards (then read the callee); then-chains
rg -H -n --pcre2 '\.(forEach|on|once|addEventListener)\([^)]*?\basync\b|\b(setTimeout|setInterval|setImmediate)\(\s*async\b' --type ts $EXCLUDE -- $TS_FILES
rg -H -n -U --pcre2 '\.(get|post|put|patch|delete|all|use)\(\s*["'"'"'`][^"'"'"'`]*["'"'"'`]\s*,(?:\s*[\w.]+(?:\([^()]*\))?\s*,)*\s*async\b' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 '\bvoid\s+[A-Za-z_$][\w$.]*\(' --type ts $EXCLUDE -- $TS_FILES
rg -H -n '\.then\(' --type ts $EXCLUDE -- $TS_FILES
# Overbroad Handling: retry wrappers; cancellation
rg -H -n --pcre2 'retryIf|shouldRetry|p-retry|axios-retry|async-retry|\bretries\s*:' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 'AbortError|signal\.aborted|ABORT_ERR' --type ts $EXCLUDE -- $TS_FILES
# Broken Error Chains: rethrow without cause; non-Error throws; stack dropped at a log call; custom error classes (then read super())
rg -H -n -U --pcre2 'catch\s*\(\s*(\w+)[^)]*\)\s*\{[^}]*?throw\s+new\s+\w+\((?![^;]*\bcause\b)[^;]*;' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 'throw\s+["'"'"'`\d]|Promise\.reject\(\s*["'"'"'`\d]' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 '(console|log\w*)\.\w+\([^)]*\b(e|err|error|ex)\.message\b' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 'class\s+\w+\s+extends\s+\w*Error\b' --type ts $EXCLUDE -- $TS_FILES
# Unmatchable Failures: message matching
rg -H -n --pcre2 '\.message\s*(===?|!==?|\.(includes|startsWith|endsWith|match)\()' --type ts $EXCLUDE -- $TS_FILES
# Untranslated Boundary Errors: library codes and types (then compare the unit with the adapter); framework transport
# errors (then look for a non-request entry point that reaches the unit)
rg -H -n --pcre2 '\.code\s*[!=]==?\s*["'"'"'](P\d{4}|\d{5}|ER_\w+)["'"'"']|instanceof\s+(Prisma\.\w+|AxiosError|QueryFailedError|MongoServerError)|isAxiosError\(' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 'throw\s+new\s+(HttpException|(BadRequest|Unauthorized|Forbidden|NotFound|Conflict|Gone|UnprocessableEntity|InternalServerError|ServiceUnavailable)Exception|TRPCError|HTTPError)\(' --type ts $EXCLUDE -- $TS_FILES
# Swallowed Errors (logged-only) and Double Handling: a catch that logs first (then read whether it throws,
# continues, or returns a default); catch that only re-throws
rg -H -n -U --pcre2 'catch\s*(\([^)]*\))?\s*\{\s*(console|log\w*)\.\w+\(' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 'catch\s*\(\s*(\w+)\s*\)\s*\{\s*throw\s+\1\s*;?\s*\}' --type ts $EXCLUDE -- $TS_FILES
# Poor Error Context: literal messages (then judge); message events only with a Tracker line (then read Sentry.init)
rg -H -n --pcre2 'throw\s+new\s+\w*Error\(\s*["'"'"'][^"'"'"'$]*["'"'"']\s*\)' --type ts $EXCLUDE -- $TS_FILES
rg -H -n --pcre2 'Sentry\.captureMessage\(\s*`[^`]*\$\{' --type ts $EXCLUDE -- $TS_FILES
# Panic and Exit Misuse: exits (then check that the file is not an entry point)
rg -H -n 'process\.exit\(' --type ts $EXCLUDE -- $TS_FILES
```

Blind spots: floating promises in general (`no-floating-promises`); a catch body with nested braces defeats the
rethrow-without-cause scan (`preserve-caught-error` covers built-in constructors only, unless `errorClassNames` is
set); a route registered through a variable path or a router builder (`route('/x').get(async …)`); `app.use(async …)`
with no path; a middleware argument with nested calls (`validate(schema(x))`); a project's own `HttpException`
subclass (reading, from the boundary pass); a `return promise` without `await` inside a `try` (routing rule 8:
`@typescript-eslint/return-await`, or reading, from another nomination in the same `try`).

## Phase 5 — TypeScript-specific evaluation

- For each `catch`: is the binding narrowed before use (an unnarrowed `e.message` is invariant-hunter's)? Does a
  rethrow carry `cause`?
- For each custom error class that drops `options`: does any call site pass `{ cause }`? None → drop.
- For each `async` route handler: what is the Express major version of its package, and does that package load an
  async wrapper?
- For each discarded promise (`void` or not): can the callee reject, or does it catch every failure itself?
- For each transport error: does a non-request entry point reach the unit that throws it?
