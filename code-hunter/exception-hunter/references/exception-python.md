# Exception Hunter — Python reference

Contents: Applicability · Generated-code and test-path eligibility · Language facts and version gates · Not a finding on these grounds alone — Python · Transport frameworks · Delegated to tools · Phase 2 — exception scans · Phase 4 — Python-specific evaluation

## Applicability

| Category | Applicable | Python note |
| -------- | ---------- | ----------- |
| Swallowed Errors | **yes** | a default returned from `except`; `suppress(…)` of a broad failure; `gather(…, return_exceptions=True)` results never read |
| Orphaned Async Failures | **yes** | a kept task or future never read; `executor.submit()` futures never read; `threading.Thread` targets that can raise |
| Overbroad Handling | **yes** | `except Exception` mapped to one meaning; retry decorators; `CancelledError` logged at error level |
| Broken Error Chains | **yes** | `raise X(str(e))` outside the `except` that caught `e`; `from None` with no reason |
| Unmatchable Failures | **yes** | text matching on `str(e)` / `e.args`; generic `raise Exception(…)`; a domain failure raised as a builtin; `except ValueError` around a `TaskGroup` |
| Untranslated Boundary Errors | **yes** | library exceptions caught outside the adapter; `HTTPException` / `Http404` / `abort()` reached by a non-request entry point |
| Double Handling | **yes** | `logger.exception(…); raise` |
| Poor Error Context | **yes** | literal messages with no input |
| Panic and Exit Misuse | **yes, exit calls only** | `sys.exit` / `os._exit` outside the entry point |

## Generated-code and test-path eligibility

A file is generated (ineligible for reporting) only when identified by an authoritative in-file marker **where one
exists** (`# Generated by …`, `# @generated`, protobuf and gRPC stub headers). Scan
globs such as `*_pb2.py` / `*_pb2_grpc.py` are approximations for scanning convenience.

Vendored and build trees (`venv/`, `.venv/`, `dist/`, `build/`, `__pycache__/`, `*.egg-info/`), lockfiles, and
Markdown-only inputs are also ineligible.

**Test paths are ineligible** (see Test-code scope in SKILL.md): `test_*.py`, `*_test.py`, `tests/`, `conftest.py`.

## Language facts and version gates

The version is `requires-python`, or the lockfile's interpreter. A remedy is proposed only when that version supports
it.

- `asyncio.CancelledError` is a `BaseException` from 3.8: `except Exception` no longer catches it; bare `except:` and
  `except BaseException` do.
- `ExceptionGroup`, `except*`, `add_note`, and `asyncio.TaskGroup`: 3.11.

## Not a finding on these grounds alone — Python

- **`suppress` of one named failure whose suppression is the intent** (`with suppress(FileNotFoundError):
  os.remove(p)`).
- **`StopIteration` and `StopAsyncIteration`**: loop termination by contract.
- **Cancel and join of a child task** that this code cancelled itself (`task.cancel()`, then `await task`), when the
  join re-raises the current task's own cancellation (`if asyncio.current_task().cancelling(): raise`, 3.11+). `with
  suppress(CancelledError): await task` does not re-raise it, so it stays a finding.

## Transport frameworks

- **FastAPI / Starlette**: `@app.exception_handler(…)` registers a mapping; `HTTPException` is mapped wherever it is
  raised on the request path. An unhandled exception becomes a 500 and the server logs it.
- **Flask**: `@app.errorhandler(…)`.
- **Django**: `Http404` and exception middleware.
- **DRF**: the `EXCEPTION_HANDLER` setting.
- **Celery**: `autoretry_for` and `self.retry(…)` on tasks; a task is a non-request entry point.

## Delegated to tools

- ruff: an `except` that only passes or continues (`S110`, `S112`, with `check-typed-exception = true`); a bare or blind
  `except` as such (`E722`, `BLE001`; what the handler does with the failure stays here); a jump in `finally` (`B012`);
  an exception built and not raised (`PLW0133`); a task created and not kept (`RUF006`); a traceback dropped at a log
  call (`TRY400`); an `except` that only re-raises (`TRY203`); an interpolated log message (`G004`). `RUF006` and `G004`
  are not in ruff's default set.

## Phase 2 — exception scans

`$PY_FILES` is this language's eligible list, restored from `<run>/python.txt` (SKILL.md Phase 1 step 4).

```bash
EXCLUDE='--glob !**/venv/** --glob !**/.venv/** --glob !**/dist/** --glob !**/build/** --glob !**/__pycache__/** --glob !**/*.egg-info/** --glob !**/*_pb2.py --glob !**/*_pb2_grpc.py --glob !**/test_*.py --glob !**/*_test.py --glob !**/tests/** --glob !**/conftest.py'

# Swallowed Errors: return a default
rg -H -n -U --pcre2 'except\b[^:\n]*:\s*\n\s*return(\s+(None|\[\]|\{\}|""|'"''"'|0|False))?\s*$' --type py $EXCLUDE -- $PY_FILES
# Swallowed Errors: suppress (then read the type); gather results
rg -H -n --pcre2 '\bsuppress\(' --type py $EXCLUDE -- $PY_FILES
rg -H -n --pcre2 'return_exceptions\s*=\s*True' --type py $EXCLUDE -- $PY_FILES
# Orphaned Async Failures: a kept task (then look for an await or a result read); executor futures; threads
rg -H -n --pcre2 '=\s*([\w.]+\.)?(create_task|ensure_future)\(' --type py $EXCLUDE -- $PY_FILES
rg -H -n --pcre2 '\.submit\(|threading\.Thread\(' --type py $EXCLUDE -- $PY_FILES
# Overbroad Handling: broad except (then read its expected failure); retry wrappers; cancellation
rg -H -n --pcre2 'except\s*(:|\(?\s*(Exception|BaseException)\b)' --type py $EXCLUDE -- $PY_FILES
rg -H -n --pcre2 '@retry\b|autoretry_for\s*=|retry_if_exception_type\(|backoff\.on_exception\(' --type py $EXCLUDE -- $PY_FILES
rg -H -n 'CancelledError' --type py $EXCLUDE -- $PY_FILES
# Unmatchable Failures: text matching; generic raises (then find the consumer); exception-group sources
rg -H -n --pcre2 '\bin\s+str\((e|err|exc|ex|error)\)|str\((e|err|exc|ex|error)\)\s*(==|!=|\.startswith|\.endswith)|\.args\[0\]\s*(==|!=)' --type py $EXCLUDE -- $PY_FILES
rg -H -n --pcre2 'raise\s+(Exception|RuntimeError)\(' --type py $EXCLUDE -- $PY_FILES
rg -H -n 'TaskGroup\(' --type py $EXCLUDE -- $PY_FILES
# Untranslated Boundary Errors: library exceptions (then compare the unit with the adapter); transport errors (then
# look for a non-request entry point that reaches the unit)
rg -H -n --pcre2 'except\b[^:\n]*\b(IntegrityError|OperationalError|SQLAlchemyError|DatabaseError|NoResultFound|ClientError|HTTPError|RequestException|ConnectionError)\b' --type py $EXCLUDE -- $PY_FILES
rg -H -n --pcre2 'raise\s+(HTTPException|Http404|\w+\.HTTPException)\b|\babort\(\s*\d{3}' --type py $EXCLUDE -- $PY_FILES
# Swallowed Errors (logged-only) and Double Handling: a handler that logs first (then read whether it raises,
# continues, or defaults)
rg -H -n -U --pcre2 'except\b[^:\n]*:\s*\n\s*log\w*\.\w+\(' --type py $EXCLUDE -- $PY_FILES
# Poor Error Context: literal messages (then judge)
rg -H -n --pcre2 'raise\s+\w+(Error|Exception)\(\s*("[^"{]*"|'"'"'[^'"'"'{]*'"'"')\s*\)' --type py $EXCLUDE -- $PY_FILES
# Panic and Exit Misuse: exits (then check that the file is not an entry point)
rg -H -n --pcre2 '\b(sys\.exit|os\._exit)\(' --type py $EXCLUDE -- $PY_FILES
```

Blind spots: a handler body with a comment line before the log call (the comment is read, not scanned); a task kept
in a collection instead of a name (reading).

## Phase 4 — Python-specific evaluation

- For each broad handler: what is its expected failure? Does it re-raise `CancelledError` in async code?
- For each `CancelledError` handler: whose cancellation is it, the current task's (finding when suppressed) or a
  child's that this code cancelled and now joins? A join is not a finding only when it re-raises when
  `current_task().cancelling()` is set.
- For each log-first handler: does it raise, continue, or default?
- For each kept task: is it awaited or its result read anywhere?
- For each `HTTPException` / `Http404` / `abort(…)`: does a non-request entry point reach the unit that raises it?
