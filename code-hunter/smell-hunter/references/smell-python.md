# Smell Hunter — Python reference

Language-specific rules for Python.

## Applicability of conditional categories

| Category | Applicable | Reason |
| -------- | ---------- | ------ |
| Primitive Obsession | **yes** | owned here as domain modeling; type-hunter keeps `NewType`/alias mechanics |
| God Module | **yes** | the `.py` file is the module unit; nothing else in the party claims it |
| Mutable Global State | **yes** | module-level mutable globals and stateful singletons |
| Anemic Domain Model | **yes** | entity/service split is common in Python codebases |
| Class Abuse | **yes** | classes standing in for modules and functions |

**Language-only category added below:** Mutable Default Arguments.

## Generated-code eligibility

A file is generated (ineligible for reporting) only when identified by an authoritative in-file marker **where one
exists** (`# Generated by …`, `# @generated`, protobuf and gRPC stub headers) — never by filename guessing. Scan
globs such as `*_pb2.py` / `*_pb2_grpc.py` are approximations for scanning convenience.

Vendored and build trees (`venv/`, `.venv/`, `dist/`, `build/`, `__pycache__/`, `*.egg-info/`), lockfiles, and
Markdown-only inputs are also ineligible.

## Language-only categories

### Mutable Default Arguments

Mutable objects as default argument values — the classic Python footgun, where the default is created once at
definition time and shared across every call.

**Signals:**

- `def func(items: list = [])`, `def func(config: dict = {})`, `def func(seen: set = set())`
- `__init__` with mutable defaults: `def __init__(self, data: list = [])`
- Dataclass fields with `default=[]` or `default={}` instead of `field(default_factory=list)`
- Functions that mutate a default parameter, producing state persistence between calls

**Action:** Use `None` as the sentinel and construct inside the function; use `dataclasses.field(default_factory=…)`
for dataclass fields.

```python
def func(items: list[str] | None = None) -> None:
    items = items if items is not None else []
```

**Severity:** **High** when the default is actually mutated (state already leaks between calls) — **Critical** if
that leak reaches a production path. **Low** when the default is only read.

**Report table:**

| # | Location | Function | Default | Risk | Severity | Impact | Action |
| - | -------- | -------- | ------- | ---- | -------- | ------ | ------ |
| 1 | cart.py:22 | `add_item(items=[])` | `[]` | Mutated — state persists between calls | High | Medium | `None` sentinel |

## Per-category Python content

### Data Clumps — Python remedies

Extract a `@dataclass` or `NamedTuple`. Signature-only clumps become a parameter dataclass; clumps recurring across
type definitions become a shared composed type. A `TypedDict` is the remedy when the group must stay a mapping at a
serialization boundary.

### Primitive Obsession — Python remedies

`NewType('UserId', str)` for identity distinctions the type checker should enforce; a frozen `@dataclass` with
`__post_init__` validation when construction must be guarded; `enum.Enum` / `StrEnum` for status values instead of
raw string comparison; `decimal.Decimal` for money instead of `float`; `datetime.timedelta` for durations instead of
a bare `int`; `TypedDict` for structured payloads currently passed as `dict[str, Any]`.

`NewType` gives no runtime validation — when the value must be *validated* on construction, that is
invariant-hunter's parse-don't-validate territory; cross-reference rather than duplicating.

### God Module — Python signals

- A module mixing unrelated functionality — line count nominates, unrelated responsibilities decide
- `utils.py`, `helpers.py`, `common.py`, `misc.py` with unbounded scope
- A module imported by nearly every other module in the project
- `__init__.py` containing business logic rather than re-exports

**Action:** Split by responsibility (`string_utils.py`, `date_utils.py`); reduce `__init__.py` to re-exports.

### Mutable Global State — Python markers

- Module-level mutable assignment (`_cache = {}`, `_registry = []`) written to by functions
- The `global` statement rebinding a module-level name
- `set_*` / `configure_*` functions mutating module-level config
- Singleton via `__new__`, `_instance`, or a metaclass, holding state
- A module-level logger, client, or session replaced at runtime

**Do not flag** module-level constants and effectively-constant tables with no write path after import.

**Singleton split (see SKILL.md).** A *stateful* singleton — `__new__`/`_instance`/metaclass holding data — is a
Mutable Global State finding, remedied by constructing in the composition root and injecting. Do **not** recommend
"replace with a module-level instance": that keeps the global lifetime and merely removes the wrapper. A *stateless*
namespace-shaped singleton is a Class Abuse finding, remedied by module-level functions.

### Anemic Domain Model — Python evidence

A finding requires misplaced *behavior*, not missing methods:

- Transitions for one entity scattered across multiple services (`UserService.activate`, `BillingService.suspend`)
- External field mutation where the entity could own it — `order.status = "shipped"` instead of `order.ship()`
- Tell-don't-ask at call sites: `if order.status == "paid": …` repeated across services instead of
  `order.can_ship()`

Not a finding: a `@dataclass` with plain functions operating on it; a DTO, config object, Pydantic request model, or
ORM row mapper with no behavior of its own.

Validation of entity invariants belongs in `__init__` / `__post_init__` — but *enforcement* findings route to
invariant-hunter. This category owns where the transition lives.

### Class Abuse — Python signals

- Class with only `__init__` and one public method (a function in disguise)
- Class with only `@staticmethod` / `@classmethod` (a module in disguise)
- Class holding no state — all methods are pure functions over their parameters
- Class used only to group functions without shared state
- `__init__` that just assigns parameters to `self` with no validation or logic
- Stateless "Service" classes receiving all data through method parameters

**Action:** single-method class → module-level function (closure for dependencies); static-only or stateless class →
module with named function exports; data holder with real behavior → keep it, or make it a dataclass.

### Temporal Coupling — Python remedies

Accept all required dependencies in `__init__` and return a fully initialized object; use a context manager to
enforce setup/teardown ordering; use factory functions; use dataclasses with required (default-less) fields to force
completeness at construction.

## Framework carve-outs

Exempt only the shape the named construct actually requires:

- **Django models** — a model *must* subclass `django.db.models.Model`. Not a Class Abuse finding, and the field
  declarations are not a Data Clump. Django's `Manager` and `Form` subclasses are likewise mandated shapes.
- **`__init_subclass__` / metaclass-driven plugin registries the project documents** — name the registry.

Explicitly **not** carve-outs, because the framework supports alternatives:

- **SQLAlchemy** — declarative mapping is conventional, not mandated; imperative (classical) mapping and the
  decorator form are supported. A stateless helper class near a mapping is still evaluated normally.
- **Pydantic** — `BaseModel` subclasses are DTOs and are already covered by the Anemic Domain Model carve-out; that
  does not exempt a stateless service class in the same file.

"This project uses SQLAlchemy" is not evidence.

## Idiom calibration

Python's duck typing, module system, first-class functions, and dynamic features are strengths, not smells. A module
of functions is the idiomatic unit of grouping — reaching for a class is what needs justification, not the reverse.
Dataclasses, `NamedTuple`, `Protocol`, descriptors, context managers, and generators eliminate whole categories of
smell; prefer them over patterns transplanted from Java or C#. Calibrate to Python conventions.

## Evidence path form

Cite findings as `file/path.py:line`.

## Phase 2 — smell scans

Test files are **included** (see Test-code scope in SKILL.md). Data Clumps and Mutable Global State exclude them, so
test setup duplication and shared test state stay with test-hunter.

```bash
EXCLUDE='--glob !**/venv/** --glob !**/.venv/** --glob !**/dist/** --glob !**/build/** --glob !**/__pycache__/** --glob !**/*.egg-info/**'
TEST_OWNED_EXCLUDE="$EXCLUDE --glob '!**/test_*.py' --glob '!**/*_test.py' --glob '!**/tests/**' --glob '!**/conftest.py'"

# Feature envy: chained attribute access across module boundaries
rg --pcre2 '\b[a-z]\w+\.[a-z]\w+\.[a-z]\w+' --type py $EXCLUDE -- $SCOPE

# Data clumps: long signatures — test setup belongs to test-hunter
rg --pcre2 'def\s+\w+\s*\([^)]{100,}\)' --type py $TEST_OWNED_EXCLUDE -- $SCOPE

# Primitive obsession: two bare str/int params in sequence, float money, raw status strings
rg --pcre2 'def\s+\w+\s*\([^)]*:\s*str\s*,[^)]*:\s*str' --type py $EXCLUDE -- $SCOPE
rg --pcre2 '(?i)(price|amount|money|cost|balance)\s*:\s*float' --type py $EXCLUDE -- $SCOPE
rg --pcre2 '\bstatus\s*==\s*[\x27"]' --type py $EXCLUDE -- $SCOPE

# Temporal coupling: init/setup/configure methods
rg -n --pcre2 'def\s+(init|setup|configure|prepare)\s*\(' --type py $EXCLUDE -- $SCOPE

# Mutable default arguments
rg -n --pcre2 'def\s+\w+\s*\([^)]*=\s*(\[\]|\{\}|set\(\))' --type py $EXCLUDE -- $SCOPE
rg -n --pcre2 'field\s*\(\s*default\s*=\s*(\[\]|\{\})' --type py $EXCLUDE -- $SCOPE

# God module: line counts over the ELIGIBLE subset only (never a bare repo-wide find)
rg --files --type py $EXCLUDE -- $SCOPE | while read -r f; do wc -l "$f"; done | sort -rn | head -20

# Class abuse candidates
rg -n 'class\s+\w+' --type py $EXCLUDE -- $SCOPE
rg -n '@staticmethod|@classmethod' --type py $EXCLUDE -- $SCOPE

# Mutable global state and stateful singletons — shared test state belongs to test-hunter
rg -n '__new__\s*\(|_instance\b|\bglobal\s+\w+' --type py $TEST_OWNED_EXCLUDE -- $SCOPE
rg -n --pcre2 '^_?\w+\s*(:\s*[^=]+)?=\s*(\[\]|\{\}|dict\(|list\(|set\()' --type py $TEST_OWNED_EXCLUDE -- $SCOPE

# Anemic domain model: entities to inspect against their services
rg -n '@dataclass|class\s+\w+Service\b|class\s+\w+Manager\b' --type py $EXCLUDE -- $SCOPE
rg -n --pcre2 '^\s*\w+\.(status|state)\s*=' --type py $EXCLUDE -- $SCOPE

# Temporary field: transient-looking attributes
rg -n --pcre2 'self\.(temp|cached|last|pending)\w*\s*=' --type py $EXCLUDE -- $SCOPE

# Comments as deodorant: comment blocks before code (inspect for "what" vs "why")
rg -n -B1 -A1 '^\s*# ' --type py $EXCLUDE -- $SCOPE | head -200
```

## Phase 5 — Python-specific evaluation

For each class:

- Does it hold state? Does it have more than one public method?
- Could it be a plain function, a module of functions, or a dataclass?
- Is it a singleton — and is it stateful (→ Mutable Global State) or stateless (→ Class Abuse)?
- Is its shape mandated by a named framework construct (see carve-outs)?

For each mutable default:

- Is it actually mutated in the body, or only read? Mutation raises Severity sharply.
- Does the surviving state reach a production path?

For each god-module candidate:

- Enumerate the unrelated responsibilities by name. If you cannot name at least two, it is not a finding.
- Does `__init__.py` carry business logic rather than re-exports?

For each entity/service pair:

- Which transitions live in the service that the entity could own? Name at least one.
- Are entity fields mutated from outside? Cite the assignment.

For each module-level mutable name:

- Is there any rebinding or in-place mutation after import? If not, it is not a finding.
