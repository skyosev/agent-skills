# Invariant Hunter — Python reference

Language-specific rules for Python.

## Applicability of universal categories

| Category | Applicable | Reason |
| -------- | ---------- | ------ |
| Unguarded Type Assertions | **yes** | `cast()` and checker-satisfying `assert x is not None` |
| Loose Optionality | **yes** | `Optional[T]` / `T \| None` fields and parameters; owned here, type-hunter keeps type design |
| Defensive Access in Non-Boundary Code | **yes** | `is not None` / `or default` on always-present values |
| Leaky Discriminated Unions | **yes** | `Literal` discriminant over dataclass variants; a **variant hierarchy** (dataclass or sealed data classes with no overridable behavior) narrowed by `isinstance`; `match`. A hierarchy whose base declares abstract or overridable behavior the consumer calls is a *contract type* → solid-hunter |
| Runtime Checks Promotable to Types | **yes** | `TypeGuard` / `TypeIs`, validated-state `NewType`, `frozen=True`, `tuple` / `frozenset` config |
| Type-System Bypasses | **yes** | `Any`, `# type: ignore`, `# pyright: ignore`, `# mypy: ignore` |

**No language-only categories.** Exception handling — bare `except`, catch-and-log, silent fallbacks, `raise from`
chaining — is error-hunter's; route, do not evaluate here.

## Generated-code and test-path eligibility

A file is generated (ineligible for reporting) only when identified by an authoritative in-file marker **where one
exists** (`# Generated by …`, `# @generated`, protobuf and gRPC stub headers) — never by filename guessing. Scan
globs such as `*_pb2.py` / `*_pb2_grpc.py` are approximations for scanning convenience.

Vendored and build trees (`venv/`, `.venv/`, `dist/`, `build/`, `__pycache__/`, `*.egg-info/`), lockfiles, and
Markdown-only inputs are also ineligible.

**Test paths are ineligible** (see Test-code scope in SKILL.md): `test_*.py`, `*_test.py`, `tests/`, `conftest.py`.
Test files are still read as context — a test that passes `None` proves the parameter is `None`-able.

## Per-category Python content

### Unguarded Type Assertions — Python markers

- `cast(T, x)` with no preceding check, or after a check on a *different* value
- `assert x is not None` written to satisfy the checker where the upstream type should be non-optional. An
  `assert` that guards a genuine runtime possibility is a guard, not a finding; the finding is the loose type it
  compensates for (→ Loose Optionality)
- Runtime-guarded `cast()` is not a finding when the type definition ties the check to the claim: `cast(LeafConfig,
  node.config)` after `if node.kind == 'leaf'` where `Node` is a `Literal`-discriminated union of dataclasses and
  `Leaf.config: LeafConfig`. The same check on one class with `kind: str` and `config: object` is a finding —
  nothing ties the check to the field

### Loose Optionality — Python forms

`Optional[T]`, `T | None`, `field(default=None)` always set before use; a `TypedDict` key marked `NotRequired` that
every producer supplies. The Evidence cell reads every constructor, factory, `__post_init__`, deserializer
(`from_dict`, Pydantic model, `dataclasses.replace`), and later assignment. A Pydantic or dataclass type exported from
a library whose documented contract permits omission → withdrawn.

### Defensive Access — Python forms

`x is not None`, `x or default`, `if x:` on an always-present value, `getattr(obj, "f", None)` on a known attribute,
`dict.get(k, default)` on a key every producer sets. Truthiness checks (`if x:`) that conflate `None` with an empty
container are named in Action.

### Leaky Discriminated Unions — Python forms

- `Literal` discriminant over `@dataclass` variants, consumed by `match` on the field or `if x.kind == …` chains
- A **variant hierarchy** — dataclass or sealed data classes with no overridable behavior — narrowed by `isinstance`,
  consumed by `isinstance` chains or `match` class patterns. When the base declares abstract or overridable behavior
  the consumer calls, it is a contract type, and a branch compensating for one implementor is solid-hunter's Broken
  Substitution
- Parallel flag: `kind` alongside `is_leaf: bool`
- Exhaustiveness enforcement counts when present: a `case _: assert_never(x)` arm, pyright `reportMatchNotExhaustive`
  enabled, or a return type that makes mypy / pyright fail on a missing case. `else: raise ValueError` is runtime
  rejection: the finding stands at Low and Action names the rejection as partial.

### Runtime Checks Promotable to Types — Python forms

- Boolean validators (`def is_user(x) -> bool`) that should be `TypeGuard[User]` or `TypeIs[User]` so the caller's
  scope narrows
- A validated value — `parse_email()` returning `str` — travelling downstream as plain `str`: a `NewType` or a frozen
  dataclass produced only by the parser. `NewType` gives no runtime validation, so the proposal names the single
  producer. A bare `user_id: str` with no validation boundary is smell-hunter's Primitive Obsession, not a finding here
- Empty-check branches that `Annotated[list[T], MinLen(1)]` or a non-empty type removes
- Mutation guards where `@dataclass(frozen=True)`, `tuple`, or `frozenset` enforce at runtime — **shallowly**. A
  nested `list` or `dict` stays mutable; the Proposed cell names it. Frozen replaces a guard only against
  reassignment of the field or element itself

### Type-System Bypasses — Python forms

- `Any` as parameter, return, or variable annotation where a concrete type, a `Protocol`, or `object` plus narrowing
  would do
- `# type: ignore` with no error code (`# type: ignore[attr-defined]` is scoped; still bare without a reason)
- `# pyright: ignore`, `# mypy: ignore`, `# pyright: basic` file directives
- `cast(Any, x)` is a bypass; `cast(T, x)` is an assertion — within-skill routing in SKILL.md

## Toolchain

**Adoption evidence:** a `[tool.mypy]` table in `pyproject.toml`, a `mypy.ini` / `setup.cfg` mypy section, a
`pyrightconfig.json` or `[tool.pyright]` table, or a typecheck step in the project's task runner or CI. Config alone
is adoption for a type checker — unlike a formatter, there is no separate "lint vs format" question.

**Execution:** read-only, the project's own invocation where one exists (a `make typecheck`, a `tox` / `nox` env, a
`pre-commit` hook), else `mypy .` / `pyright` from the repository root when installed in the active environment.
Never install. Record `mypy: ran — <command>, <version>, <targets>` / `skipped — not configured` /
`skipped — configured, not installed` / `errored — <message>`. Read strictness flags from the config regardless of
whether the tool ran: `strict`, `disallow_any_generics`, `disallow_untyped_defs`, `warn_return_any`,
`reportMatchNotExhaustive`, `reportOptionalMemberAccess`. Flags off → findings still reported; one Low
recommendation names the flag; recorded in Scope.

Tool output is a nomination list: a `union-attr` or `reportOptionalMemberAccess` error is a Loose Optionality or
Defensive Access candidate, not a finding.

## Idiom calibration

`Optional` on a public library parameter that genuinely serves optional and required callers is the language working
as designed. `if x is None: raise` at a trust boundary is validation, not defensive access. `assert` used for a real
runtime check in a `__post_init__` is a guard. `Protocol` and duck typing are not bypasses; `Any` is.

## Evidence path form

Cite findings as `file/path.py:line`.

## Phase 2 — invariant scans

Test files are **excluded** (see Test-code scope in SKILL.md). Every scan takes the eligible Python list.

```bash
EXCLUDE='--glob !**/venv/** --glob !**/.venv/** --glob !**/dist/** --glob !**/build/** --glob !**/__pycache__/** --glob !**/*.egg-info/** --glob !**/*_pb2.py --glob !**/*_pb2_grpc.py --glob !**/test_*.py --glob !**/*_test.py --glob !**/tests/** --glob !**/conftest.py'

# Unguarded Type Assertions
rg -n '\bcast\(' --type py $EXCLUDE -- $SCOPE
rg -n 'assert\s+\w[\w.]*\s+is\s+not\s+None' --type py $EXCLUDE -- $SCOPE

# Loose Optionality: optional declarations (then read every producer and later write)
rg -n --pcre2 'Optional\[|:\s*[\w\[\], ]+\|\s*None\b|\|\s*None\s*=|field\(default=None' --type py $EXCLUDE -- $SCOPE

# Defensive Access: None checks and defaults (then locate the boundary)
rg -n 'is not None|is None|\bor\s+["\x27\[\{0]|getattr\([^,]+,[^,]+,\s*None\)' --type py $EXCLUDE -- $SCOPE

# Leaky Discriminated Unions: discriminants, match, isinstance chains, exhaustiveness adoption
rg -n 'Literal\[' --type py $EXCLUDE -- $SCOPE
rg -n '^\s*match\s+\w|^\s*case\s+_\s*:|isinstance\(' --type py $EXCLUDE -- $SCOPE
rg -n 'assert_never|TypeGuard|TypeIs' --type py $EXCLUDE -- $SCOPE     # the source's escaped pipe matched nothing

# Runtime Checks Promotable to Types: validators returning bool, NewType, frozen, Annotated
rg -n --pcre2 'def\s+(is_|has_|valid|check)\w*\([^)]*\)\s*->\s*bool' --type py $EXCLUDE -- $SCOPE
rg -n 'NewType\(|frozen=True|Annotated\[' --type py $EXCLUDE -- $SCOPE

# Type-System Bypasses
rg -n ':\s*Any\b|->\s*Any\b|\[Any\]|cast\(Any,' --type py $EXCLUDE -- $SCOPE
rg -n '#\s*type:\s*ignore|#\s*(pyright|mypy):\s*(ignore|basic)' --type py $EXCLUDE -- $SCOPE
```

## Phase 5 — Python-specific evaluation

For each `cast()`:

- Is there a preceding check on the same value, and does the type definition tie it to the claim (variant class,
  `Literal`-discriminated dataclass)? Yes → not a finding. Check on a different value, or one class with `kind: str`
  → finding.
- `cast(Any, …)` → Type-System Bypasses, not here.

For each `assert x is not None`:

- Can `x` be `None` at runtime here? Yes → a guard; the loose upstream type is the candidate. No → the assertion is
  checker-satisfying and the finding.

For each `Optional` / `| None` field:

- Every producer read? Every later assignment, `replace`, deserializer? Is the type constructible outside the
  repository with a contract that permits omission? Then withdraw and record the limitation.
- Two optionals never both set, no discriminant → smell-hunter's Temporary Field; cross-reference.

For each `is not None` / `or default`:

- Is the value already resolved at the entry point? Then Defensive Access. Is the type already non-optional? Then
  simplicity-hunter's Dead Code Paths. At a trust boundary → not a finding.

For each `match` / `isinstance` chain over a union:

- Is it a union of data shapes, or a **contract type** whose base declares overridable behavior the consumer calls?
  Contract type, with a branch compensating for one implementor → solid-hunter's Broken Substitution;
  cross-reference, do not score.
- Must the consumer cover every variant, or does it handle a subset by design?
- Is `assert_never` present, or `reportMatchNotExhaustive` enabled, or does the return type force the checker? Any →
  not a finding. `else: raise` → Low, partial.

For each `# type: ignore` / `# pyright: ignore`:

- Error code present? Reason present and confirmed by the code? Boundary layer or domain code? Bare in domain code is
  the finding.

For each `frozen=True` / `tuple` proposal:

- What nested content stays mutable? Name it in Proposed.
