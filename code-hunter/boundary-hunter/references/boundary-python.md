# Boundary Hunter — Python reference

## Applicability of the categories

| Category | Applicable | Reason |
| -------- | ---------- | ------ |
| Dead Exports | **yes** | Export = a name in `__all__` or re-exported by a package `__init__.py`, **for this category only**. A plain non-underscore name has no "unexport" edit: with zero importers it is simplicity-hunter's Dead Code Paths, with intra-package importers only it is nothing. PEP 420 namespace packages have no `__init__` surface, so only a module `__all__` applies |
| Leaked Internals | **yes** | Judges **any** consumed non-underscore name, whatever `__all__` says, plus the `__init__` re-exporting a `_name` form |
| Deep Imports | **yes** | `pkg._x` and `pkg.internal.x` are deep whatever the `__init__` holds; bypassing an `__init__` that re-exports is the other form. Python has **no enforcement mechanism** — the remedy vocabulary is convention and `import-linter` contracts, never `internal/` |
| Dependency Direction Violations | **yes** | Module edges. An `import-linter` `layers` contract is the one machine-readable ordering this suite reads |
| Cyclic Dependencies | **yes** | Module graph. Kind by erasure of `TYPE_CHECKING`-guarded edges; Failure provable by reading a module-level partner read against definition order |
| External Type Leaks | **yes** | External = not stdlib (`sys.stdlib_module_names`) and not a first-party package declared by a repository `pyproject` |
| Generic Boundary Names | **yes** | Package unit. No `clause ≠ directory` form: the package name *is* the directory name |

## Generated-code and test-path eligibility

A file is generated (ineligible for reporting) only when identified by an authoritative in-file marker where one
exists (`# Generated by …`, `# @generated`, protobuf and gRPC stub headers). Scan globs
such as `*_pb2.py` / `*_pb2_grpc.py` are approximations for scanning convenience.

Vendored and build trees (`venv/`, `.venv/`, `dist/`, `build/`, `__pycache__/`, `*.egg-info/`), lockfiles, and
Markdown-only inputs are also ineligible.

**Test paths are ineligible** (see Test-code scope in SKILL.md): `test_*.py`, `*_test.py`, `tests/`, `conftest.py`.

## Python principles

- **Privacy is convention.** The `_` prefix enforces nothing; there is no `internal/`, no `exports` field. That is why
  the remedy vocabulary here is "remove from `__all__`", "stop re-exporting", "state the surface", and an
  `import-linter` contract — never a mechanism the language does not have.
- **Import executes code.** A module body runs on first import, so a cycle is not only a structural defect: the order
  in which two partially initialized modules read each other decides whether the process starts.
- **`__all__` is one way among several.** A missing `__all__` is not a finding. The Dead Exports gate needs an
  *explicit* surface precisely because a public name with no `__all__` has no edit this skill can name.
- **A name can be consumed by string.** `[project.entry-points]`, `[project.scripts]`, Django `INSTALLED_APPS` /
  `MIDDLEWARE` / `AUTH_USER_MODEL`, Celery task names, pytest plugin names, template and serializer paths. The string
  is the consumer.
- **A package is its directory.** There is no clause-vs-directory mismatch to find, and no re-export surface in a PEP
  420 namespace package.

## Boundary unit, public entry, export, publication

- **Boundary unit** — a package: a directory with `__init__.py`. Where no package structure exists, a standalone
  module. A PEP 420 namespace package (a directory with no `__init__.py`) is a unit with **no re-export surface**.
- **Public entry** — the `__init__.py` when it re-exports names. Independent of any `__init__`, a `_`-prefixed module
  and an `internal` / `_internal` package are implementation: a package with an empty `__init__.py` still has deep
  imports of that form.
- **Export (Dead Exports only)** — a name in `__all__`, or a name a package `__init__.py` re-exports. Nothing else.
  A plain non-underscore module-level name is **not** an export for this category: zero importers anywhere →
  simplicity-hunter's Dead Code Paths; intra-package importers only → nothing here.
- **Leaked Internals and Deep Imports do not use that gate.** A consumed non-underscore name is judged by the rewrite
  test whatever `__all__` says; a deep import is judged by the path reached.
- **External consumer** — an import from outside the package in a non-test file, plus string references.
- **Publication** — per SKILL.md Terms › Published unit.

## Layer map, prohibitions, and policy

- **Layer map sources**, in precedence: repository instructions and named ADR files; then an `import-linter`
  **`layers`** contract (`[tool.importlinter]` in `pyproject.toml`, or `.importlinter` / `setup.cfg`), which is the
  one contract type that *is* an ordering; then conventional sibling directory names from the fixed vocabulary —
  inner `domain`, `core`, `entities`; middle `application`, `usecase`, `usecases`; edge `infra`, `infrastructure`,
  `adapters`, `persistence`, `db`, `transport`, `http`, `handlers`, `controllers`, `cli`, `ui`, `web`.
- **Prohibition sources**: `import-linter` `forbidden` and `independence` contracts. Each is evidence for the edges it
  names; neither becomes a tier.
- **Policy**: `import-linter` `protected` contracts and any contract that explicitly permits an edge (a `layers`
  contract's `containers` / `ignore_imports` entries), plus repository instructions.

## External types

External = a module not in `sys.stdlib_module_names` and not a first-party package declared by a repository
`pyproject.toml` / `setup.cfg` (`[project]`, `[tool.poetry]`, `packages`, `py_modules`). `sqlalchemy.Session`,
`django.http.HttpRequest`, `flask.Request`, `pydantic.BaseModel` from a third-party import are external; `pathlib.Path`,
`datetime.datetime`, `decimal.Decimal` are stdlib and never leaks.

Marker-generated declarations (`_pb2` messages, generated client stubs) and ORM model classes are external types by
stated policy, whoever owns the schema.

## Per-category Python content

### Dead Exports — Python forms

- `zero consumers` — the `__all__` entry or `__init__` re-export has no importer outside the package, no string
  reference, and the unit is closed. Action: remove it from `__all__` / the `__init__`.
- `test only` — the only importer is a test path.
- `consolidated barrel` — `from .impl import *` in an `__init__.py` exposing N symbols nothing outside imports is
  **one** row: a representative symbol, `Occurrences: N`, Action "explicit named re-exports of the public API". A
  consumed `_name` coming through the same wildcard — possible only when the submodule's `__all__` lists it, since
  `import *` otherwise skips `_` names — gets its own Leaked Internals row.

**Enumeration caveat:** `import *`, `importlib.import_module`, `getattr(mod, name)`, and aliased imports defeat name
grep. Read the importers; search the bare name in `pyproject.toml`, settings modules, templates, and configuration.

### Leaked Internals — Python forms

Any consumed non-underscore name whose member fails the rewrite test: a function returning the module's internal
`_Index` dict, a class exposing `_cache` a consumer reads, a dataclass whose fields are the serialization format. Plus
the Python-specific form: **an `__init__.py` re-exporting a `_name`**, with an external consumer — the package
published what it marked private.

### Deep Imports — Python forms

- `from pkg._impl import x` / `import pkg._impl` — the private path is the entry bypassed, whatever `pkg/__init__.py`
  holds (including an empty one).
- `from pkg.internal.helper import x` — same.
- `from pkg.submodule import x` where `pkg/__init__.py` re-exports `x` — the `__init__` surface is the entry.

**No enforcement vocabulary.** The Action is "import from `pkg`" plus, where the project already uses `import-linter`,
a `forbidden` contract naming the private module. Never `internal/`, never an `exports` field.

### Dependency Direction Violations — Python content

Module edges. A `TYPE_CHECKING`-guarded import that crosses layers outward is still an edge and still a finding —
erasure classifies *cycles*, not direction. The Action order: move the type to its owner; inject from the composition
root; a Protocol declared **in the inward module** only where the import cannot otherwise be broken.

### Cyclic Dependencies — Python content

- **Kind.** Edges inside `if TYPE_CHECKING:` blocks are **erased**. A cycle is `runtime` when it survives removal of
  every erased edge, `type-only` when it does not — including a cycle with one runtime edge and one
  `TYPE_CHECKING` edge, which is **type-only**.
- **Failure `provable`** — module `b` reads a binding of partner `a` at module level (`from a import X`, `a.X`, or a
  module-level call into a function whose body reads `a.X`, one hop) **and** `a` defines `X` after its own
  `import b`. On an entry that starts at `a`, `b` runs against a partially initialized `a` and raises `ImportError`
  or `AttributeError`. Recorded `provable from {entry}: {file:line}`.
- **Production entry list**: the `[project.scripts]` target, `__main__.py`, `manage.py` / `wsgi.py` / `asgi.py`, a
  framework's discovery order (Django `INSTALLED_APPS`, Celery autodiscovery), or a package `__init__` whose import
  sequence fixes which partner loads first.
- **Read the failure; never run `python -c "import a"`.** Importing project modules executes arbitrary code inside an
  audit. The failure is read, or cited from an existing log or CI output (`observed:`).

### External Type Leaks — Python content

- `signature` — an inward module's exported function, method, or attribute annotated with an external type:
  `def save(self, session: Session) -> None`.
- `re-export` — an inward module re-exporting or aliasing an external type as its own API: `from sqlalchemy.orm import
  Session`, then `Session` in `__all__`; `User = models.User`.
- `mapper output` — a conversion into an inward type whose result still carries an external type or its enum values.

Edge-tier modules (`infra/*`, `adapters/*`, `http/*`) are the wrapping layer and never findings. A private
(underscore) helper in an inward module taking an external type is not this category — it judges the exported API.

### Generic Boundary Names — Python content

A package named `util`, `utils`, `common`, `helpers`, `shared`, `misc`, `base`, `models`, `types`, `lib` **and**
exporting two or more unrelated capabilities, enumerated. A `models` package holding types for unrelated domains is
the common form. No `clause ≠ directory` form exists. A generic-named *module file* (`helpers.py`) is smell-hunter's
God Module.

## Toolchain

One tool, present-only, read-only:

```bash
# Only when import-linter is configured and installed. No --config: it finds setup.cfg, .importlinter, or
# pyproject.toml itself; pass --config only to name the file the contract was found in.
lint-imports
```

Its output nominates direction and cycle candidates and confirms that the project's own contracts hold; it is never a
finding by itself, and a contract's *text* is what supplies the layer map or the prohibition. Record `lint-imports:
ran — {command}, {version}, {contracts checked}` / `skipped — not configured` / `skipped — not installed` /
`errored — {message}`.

The graph is built from the import scan.

## Phase 2 — graph build

Nodes are modules (`pkg.sub.mod`), edges are `import` and `from … import` statements resolved to modules. Relative
imports (`from . import x`, `from ..pkg import y`) resolve against the importing module's package. An edge inside an
`if TYPE_CHECKING:` block is tagged **erased**; every other edge is **runtime**. A `__init__.py` re-export is an edge
from the package to the submodule.

The graph scans keep generated files (`_pb2`, generated clients): their imports are edges.

```bash
GRAPH_EXCLUDE='--glob !**/test_*.py --glob !**/*_test.py --glob !**/tests/** --glob !**/conftest.py --glob !**/.venv/** --glob !**/venv/** --glob !**/build/** --glob !**/dist/**'

# Graph: all import statements
rg -n --pcre2 '^\s*(from\s+[\w.]+\s+import|import\s+[\w.]+)' --type py $GRAPH_EXCLUDE -- .

# Erased edges: TYPE_CHECKING blocks (read the block to attribute the imports)
rg -n 'if\s+TYPE_CHECKING' --type py $GRAPH_EXCLUDE -- .
```

## Phase 3 — Python scans

`$PY_FILES` is this language's eligible list, restored from `<run>/python.txt` (SKILL.md Phase 1 step 4).

```bash
EXCLUDE='--glob !**/test_*.py --glob !**/*_test.py --glob !**/tests/** --glob !**/conftest.py --glob !**/.venv/** --glob !**/venv/** --glob !**/build/** --glob !**/dist/** --glob !**/*_pb2.py --glob !**/*_pb2_grpc.py'

# Dead Exports: the explicit surface
rg -H -n '__all__\s*=' --type py $EXCLUDE -- $PY_FILES
rg -H -n --pcre2 '^\s*from\s+\.[\w.]*\s+import' --glob '**/__init__.py' $EXCLUDE -- $PY_FILES | rg '(^|/)__init__\.py:'   # glob covers `.`; the filter covers file lists

# Dead Exports / consolidated form: wildcard re-exports
rg -H -n --pcre2 '^\s*from\s+\.?[\w.]*\s+import\s+\*' --type py $EXCLUDE -- $PY_FILES

# Leaked Internals: a private name re-exported by a package __init__
rg -H -n --pcre2 '^\s*from\s+\.[\w.]*\s+import\s+.*\b_\w+' --glob '**/__init__.py' $EXCLUDE -- $PY_FILES | rg '(^|/)__init__\.py:'   # glob covers `.`; the filter covers file lists

# Deep Imports: private and internal paths reached from outside
rg -H -n --pcre2 '^\s*(from|import)\s+[\w.]*\.(_\w+|internal|_internal)\b' --type py $EXCLUDE -- $PY_FILES

# Cyclic Dependencies: deferred imports inside functions (nomination only)
rg -H -n --pcre2 '^\s{4,}(from\s+[\w.]+\s+import|import\s+[\w.]+)' --type py $EXCLUDE -- $PY_FILES

# External Type Leaks: third-party names in annotations (read the module's tier first)
rg -H -n --pcre2 '^\s*(def|async def)\s+\w+\(.*:\s*\w+\.' --type py $EXCLUDE -- $PY_FILES

# Contracts and policy
rg -n 'tool\.importlinter|^\[importlinter' pyproject.toml setup.cfg .importlinter 2>/dev/null

# String references (consumers) — packaging files, then settings modules found project-wide
rg -n 'entry.points|\[project\.scripts\]' pyproject.toml setup.cfg setup.py 2>/dev/null
rg -n 'INSTALLED_APPS|MIDDLEWARE|AUTH_USER_MODEL' --glob '**/settings*.py' --glob '**/settings/*.py' -- .
```

## Phase 5 — Python-specific evaluation

For each `__all__` entry and `__init__` re-export:

- Importers outside the package, read (not grepped), string references included? None and the unit **closed** →
  Dead Exports. Only tests → `test only`. Unit **open** → withdraw with a `Limitation` line.
- Consumed, and does a member fail the rewrite test with a statable reason? → Leaked Internals. A re-exported `_name` with an external consumer → Leaked Internals; the Exposed member reason is
  `marked private by its own _ prefix`, and no further rewrite test applies.

For each plain non-underscore module-level name:

- Zero importers anywhere → **simplicity-hunter's** Dead Code Paths; cross-reference, do not score.
- Intra-package importers only → nothing here.
- Consumed from outside and failing the rewrite test → Leaked Internals (the `__all__` gate does not apply).

For each import edge:

- Reaches a `_module` or an `internal` package from outside its parent → Deep Imports, whatever the `__init__` holds.
- Bypasses an `__init__` that re-exports the same name → Deep Imports.
- Crosses tiers outward under a recorded map, or is named by a `forbidden` / `independence` contract → Dependency
  Direction Violations (precedence over Deep Imports on the same edge).
- Explicitly permitted by a contract or instructions → `Policy:`, withdrawn.

For each cycle:

- Remove every `TYPE_CHECKING` edge. Cycle survives → `runtime`; gone → `type-only`.
- `runtime`: is there a module-level partner read (`from a import X`, `a.X`, or a one-hop module-level call) whose
  binding `a` defines after its own `import b`? → `provable`, with the entry named and whether it is a production
  entry. No such read → `none observed`.
- `type-only` crossing layers → report the crossing edge as Dependency Direction Violations with the cycle named in
  Evidence.

For each exported annotation in an inward-tier module (boundary source required):

- Names a non-stdlib, non-first-party, or marker-generated type → `signature`; an alias or re-export of one →
  `re-export`; a conversion still carrying one → `mapper output`. Edge tier, or no boundary source → no finding.
