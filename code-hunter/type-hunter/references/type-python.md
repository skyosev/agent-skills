# Type Hunter — Python reference

Contents: Applicability of the universal categories · Generated-code and test-path eligibility · Per-category Python content · Phase 2 — type scans · Phase 4 — Python-specific evaluation

## Applicability of the universal categories

| Category | Applicable | Reason |
| -------- | ---------- | ------ |
| Duplicated Type Declarations | **yes** | Sibling type: `TypedDict`, dataclass, or Pydantic model inheritance; `Required` / `NotRequired` for omittable-key variants; delete-and-use for a `Literal` beside an `Enum` and for duplicate aliases. Schema only where the model itself can replace the copy at every site. No runtime-value derivation: a `Literal` beside a tuple of the same strings is Not a finding |
| Generics That Never Vary | **yes** | `TypeVar` / `Generic[T]` and PEP 695 `class C[T]` / `def f[T]`; type arguments are inferred at call sites and read, not scanned |
| Loose Type Parameter Constraints | **yes** | An unbounded `TypeVar` whose body compares, calls methods, or bridges with `cast`; missing `bound=` or constraints |
| Over-Powered Type Constructs | **yes** | `ParamSpec` / `Concatenate` where a callable `Protocol` suffices; an `@overload` tower where a union or a bound `TypeVar` keeps every input→output mapping |
| Enum Construct Mechanics | **yes** | `.value` compared against raw strings; a single-member `Enum` |
| Alias vs Named Type Mechanics | **yes** | Two aliases of one primitive mixed at a call site |

**No Python-only categories.**

## Generated-code and test-path eligibility

A file is generated (ineligible for reporting) only when identified by an authoritative in-file marker where one
exists (`# Generated by …`, `# @generated`, protobuf and gRPC stub headers). Scan globs such as `*_pb2.py` /
`*_pb2_grpc.py` are approximations for scanning convenience.

Vendored and build trees (`venv/`, `.venv/`, `dist/`, `build/`, `__pycache__/`, `*.egg-info/`), lockfiles, and
Markdown-only inputs are also ineligible.

**Test paths are ineligible** (see Test-code scope in SKILL.md): `test_*.py`, `*_test.py`, `tests/`, `conftest.py`.

## Per-category Python content

### Duplicated Type Declarations — Python consolidation paths

Python has no `Pick`, no `Partial`, and no derivation from a runtime sequence; the paths below are the ones that
exist. A Pydantic model can build optional variants at runtime (`create_model`); that yields no static field types and
is not a path.

- **Two `TypedDict`s / dataclasses / models, one a subset of the other** → inheritance (`class UserSummary(User)` for
  a superset; for a subset, the base becomes the smaller shape and the larger inherits from it — the Action names
  which declaration becomes the base). Every member mapped; a modifier change is expressed by `Required` /
  `NotRequired` on a `TypedDict` (3.11+, or `typing_extensions`), by defaults on a dataclass, by `Optional` with a
  default on a model.
- **A patch type with every field optional over a dataclass or model** → **no path**. Python cannot derive it
  statically. Not a finding.
- **A Pydantic model beside a `TypedDict` of the same shape** → a finding only when the `TypedDict` is deleted and the
  model used at every former site (a FastAPI `response_model`, a function that already receives the model;
  `delete UserOut`). `model_dump()` returns `dict[str, Any]`, so the `TypedDict` can neither derive from nor inherit
  the model; where it types values built by hand from `model_dump()`, neither can be dropped → no finding.
- **A `Literal[...]` beside an `Enum` with the same members** → delete-and-use (`delete the Literal`, use the `Enum`
  at every former site). Reported here, cross-referenced from Enum Construct Mechanics. This skill states no
  preference between `Enum` and `Literal` where only one exists.
- **Two aliases of one shape** (`UserMap = dict[str, User]`, `UserDict = dict[str, User]`) → delete-and-use.
- **A complex inline expression repeated at independent sites**
  (`Callable[[int, str, bool, dict[str, Any]], Awaitable[str]]` written four times) → an alias
  (`Handler: TypeAlias = Callable[...]`, or `type Handler = Callable[...]` at 3.12+). A callable `Protocol` with
  `__call__` only when the sites use keyword arguments or overloads. Written once → not a finding.

### Generics That Never Vary — Python forms

`class Cache(Generic[T])` / `class Cache[T]` instantiated only as `Cache[User]`; `def first[T](xs: list[T]) -> T` with
one call site; `Generic[T]` where `T` appears in one field and every instantiation agrees. Instantiations are read from
annotations (`Cache[User]`), explicit subscripts (`Cache[User]()`), and inferred constructions (`Cache(users)`),
project-wide. Closed and open units follow the Python rows of **Closed consumer set** in SKILL.md Terms.

### Loose Type Parameter Constraints — Python forms

- `T = TypeVar("T")` whose body uses `+`, `<`, or a method → `bound=` a `Protocol` naming the operation
  (`SupportsAdd`, `SupportsLessThan`) or the base class every instantiation shares
- `T = TypeVar("T")` where every instantiation is one of a small set (`int`, `str`) and the body needs the set →
  constraints `TypeVar("T", int, str)`
- A `cast(T, x)` or `cast(Any, x)` inside a generic body that a bound removes → one finding here
- PEP 695 `def f[T](x: T)` with the same defects → `[T: Protocol]` or `[T: (int, str)]`

### Over-Powered Type Constructs — Python forms

- **`ParamSpec` / `Concatenate` decorator typing** applied to one decorated signature → a callable `Protocol` or a
  concrete `Callable` types it at equal precision. Applied to several differing signatures → the power is needed; no
  finding.
- **`@overload` towers** where every overload maps to the same return type → a union parameter. Where the overloads
  map `int → int`, `str → str`, a union *loses* the mapping; a `TypeVar` bound to `int | str` keeps it and is the
  simpler form only if every use type-checks under it. Otherwise no finding.

### Enum Construct Mechanics — Python forms

- **`.value` compared against raw strings** (`if color.value == "red"`) — the paying consumer is the comparison site;
  the member is the intended comparand. Action: compare members (`color is Color.RED`, `color == Color.RED`);
  `StrEnum` offered as vocabulary only where `requires-python >= 3.11` and string behaviour of the members is wanted.
- **A single-member `Enum`** — a constant, not an enumeration. Action: a module constant.
- **A `Literal[...]` parallel to an `Enum`** → Duplicated Type Declarations (above), cross-referenced here.
- **Not findings:** `class Color(str, Enum)` by itself — `StrEnum` changes `str()` and `format()` of members, and
  availability does not justify the swap; an `Enum` member validated from external input with no guard
  (→ invariant-hunter / security-hunter); raw strings compared with no `Enum` anywhere (→ smell-hunter Primitive
  Obsession, which names `Enum` / `StrEnum` / `Literal` as remedy).

### Alias vs Named Type Mechanics — Python forms

Two aliases of one primitive (`UserId: TypeAlias = str`, `OrderId: TypeAlias = str`, or `type UserId = str` at 3.12+)
with a **mixing site**: a call that passes a `UserId`-annotated value where an `OrderId` is declared, or the reverse
(`link(order_id, user_id)` against `def link(user: UserId, order: OrderId)`). The alias was meant to prevent exactly
that and cannot. Action: `NewType("UserId", str)`, `NewType("OrderId", str)`.

**Not findings:** `def transfer(src: UserId, dst: UserId)` called with the arguments swapped — both are `UserId`;
`NewType` would not catch it. A bare `src: str, dst: str` with no alias — smell-hunter's. One alias, no mixing site —
documentation, not a defect.

## Phase 2 — type scans

`$PY_FILES` is this language's eligible list, restored from `<run>/python.txt` (SKILL.md Phase 1 step 4).

Every scan takes the eligible Python list.

```bash
EXCLUDE='--glob !**/venv/** --glob !**/.venv/** --glob !**/dist/** --glob !**/build/** --glob !**/__pycache__/** --glob !**/*.egg-info/** --glob !**/*_pb2.py --glob !**/*_pb2_grpc.py --glob !**/test_*.py --glob !**/*_test.py --glob !**/tests/** --glob !**/conftest.py'

# Duplicated Type Declarations: class census (then compare field sets by concept, project-wide)
rg -H -n --pcre2 '^\s*@dataclass|^\s*class\s+\w+\((.*\b(TypedDict|BaseModel|NamedTuple|Struct)\b.*)?\)?:' --type py $EXCLUDE -- $PY_FILES

# Duplicated Type Declarations: Literal groups (then look for an Enum with the same members)
rg -H -n 'Literal\[' --type py $EXCLUDE -- $PY_FILES

# Duplicated Type Declarations: inline Callable expressions (then count independent sites)
rg -H -n 'Callable\[\[' --type py $EXCLUDE -- $PY_FILES

# Generics That Never Vary / Loose Type Parameter Constraints: TypeVar, ParamSpec, Generic, Protocol subscripts
rg -H -n 'TypeVar\(|ParamSpec\(|TypeVarTuple\(|Generic\[|Protocol\[' --type py $EXCLUDE -- $PY_FILES

# PEP 695 type parameter lists (3.12+)
rg -H -n --pcre2 '^\s*(def|class)\s+\w+\[' --type py $EXCLUDE -- $PY_FILES

# Over-Powered Type Constructs: overload towers and Concatenate
rg -H -n '@overload' --type py $EXCLUDE -- $PY_FILES
rg -H -n 'Concatenate\[' --type py $EXCLUDE -- $PY_FILES

# Enum Construct Mechanics: Enum classes (then read the members and the comparison sites)
rg -H -n --pcre2 'class\s+\w+\(.*\b(Enum|StrEnum|IntEnum|IntFlag|Flag)\b' --type py $EXCLUDE -- $PY_FILES
rg -H -n '\.value\s*(==|!=|in\b)' --type py $EXCLUDE -- $PY_FILES

# Alias vs Named Type Mechanics: aliases (then look for two over one primitive, and their mixing sites)
rg -H -n --pcre2 'TypeAlias\b|^\s*type\s+\w+\s*=' --type py $EXCLUDE -- $PY_FILES
```

**Version gate:** `rg -n 'requires-python' pyproject.toml`; a gate not met removes the vocabulary — `StrEnum` 3.11+; PEP 695 and the `type` statement 3.12+;
`Required` / `NotRequired` from `typing` 3.11+ (else `typing_extensions`, if already a dependency).

## Phase 4 — Python-specific evaluation

For each pair of classes nominated as duplicates:

- Is either a mirror of a `_pb2` message, an ORM model (SQLAlchemy, Django), or an SDK type? → not this category
  (SKILL.md Terms, Cross-layer mirror); stop.
- Name the concept, map every field. Which path exists — inheritance, `Required` / `NotRequired`, delete-and-use?
  A patch type with every field optional, or a model-beside-`TypedDict` where neither can be deleted → drop.
- For delete-and-use: read every former site of the deleted copy. Any site that does not accept the survivor → drop
  (no consolidation path). A site that could not be read → withdraw with a `Limitation`.
- A `Literal` beside an `Enum` with the same members → here, cross-referenced from Enum Construct Mechanics.

For each `TypeVar` / PEP 695 parameter:

- Enumerate instantiations from annotations, subscripts, and inferred constructions, tests marked. One production
  type, set closed → Generics That Never Vary; the Action names the test fake's replacement. In an open unit (SKILL.md
  Terms, Closed consumer set) → withdraw with a `Limitation`.
- What does the body do with `T`? Opaque → no Loose finding. `+`, `<`, a method, a `cast` → Loose, with the bound or
  constraints every instantiation satisfies.

For each `ParamSpec` / `@overload` group:

- How many differing signatures does the `ParamSpec` decorate? One → Over-Powered; several → no finding.
- Do the overloads map inputs to distinct outputs? Yes → a union loses the mapping; only a bound `TypeVar` that
  type-checks on every use is simpler. No → union.

For each `Enum` and each pair of aliases over one primitive: apply the Enum Construct Mechanics and Alias vs
Named Type Mechanics Python forms above.
